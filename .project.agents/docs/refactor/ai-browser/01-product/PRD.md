## 1. 一句话定位

问学是一款专门用于 AI 网页任务的 Chromium 浏览器。用户以通用任务组织工作，在任务内像普通
浏览器一样搜索、访问和管理多个网页，并可随时唤出问学 AI，让 Agent 在当前任务的一个或多个
标签页中完成 research、答题、资料录入及其他网页操作。

问学不预设 Research、答题等固定任务模式。场景由用户的自然语言指令和当前网页决定，系统不得
把一个用户任务自动拆成多个用户可见任务。

## 2. 背景与问题

当前问学由桌面启动器、独立 Chrome for Testing 与 MV3 插件组成，已经具备完整的网页 Agent、
多标签编排、视觉观察、模型配置、任务历史、人工接管和专项答题能力，但产品体验仍存在以下问题：

1. 启动器与实际工作浏览器分离，用户需要在两个产品表面之间切换。
2. 浏览器标签页、插件对话与用户工作目标之间没有一等关联，长任务难以恢复和管理。
3. 浏览器 UI 与生命周期由 Chrome for Testing 决定，问学无法提供原生任务列表、任务级标签集合
   和统一 AI 入口。
4. Chrome for Testing 面向测试而非正式日常浏览，问学缺少自主的浏览器更新、安全和品牌体验。
5. 如果直接重写插件，现有已验证能力容易在迁移中退化。

因此，新版本应把浏览器本身变成问学产品，同时将“现有插件能力完整迁移”设为首版发布门禁。

## 3. 产品目标

### G1. 通用任务工作空间

用户可以创建多个通用任务。每个任务独立持有自己的标签页集合、当前标签页、问学 AI 会话和运行
状态，并拥有独立持久化的网站身份与浏览器资料。任务之间不共享 Cookie、网站登录态或站点存储。

### G2. 完整浏览器基础能力

问学应具备完成真实网页任务所需的基础浏览器能力，包括地址与搜索、页面导航、标签管理、下载、
文件上传、页面查找、缩放、权限处理、登录态持久化和崩溃恢复。

### G3. 问学插件功能完全迁移

当前问学插件的用户可见能力和关键行为均为 P0 基线。浏览器化迁移不得以“后续补齐”为由删除、
降级或改变其核心语义。

### G4. 任务内多标签 Agent

Agent 可以在当前任务内创建、切换、读取和操作多个标签页，并在跨页过程中保持同一任务上下文；
Agent 不得读取或操作其他任务的标签页。

### G5. 用户在场与可控

用户可以查看执行过程、停止任务、人工接管、暂停和恢复。涉及登录、验证码、权限确认、提交、
购买、删除等敏感或不可逆动作时，系统应把控制权交还用户。

### G6. 浏览器性能与安全可用

AI 空闲时不应对普通浏览造成可感知负担；浏览器应维持 Chromium 的多进程、安全隔离和 GPU 加速
能力，并建立稳定的安全更新与跨平台发布机制。

## 4. 目标用户与典型场景

以下场景是同一通用任务模型的使用示例，不是需要用户预先选择的产品模式。

| 用户           | 典型任务                                                     |
| -------------- | ------------------------------------------------------------ |
| 学生与研究人员 | 搜索多个来源、比较观点、整理材料并生成带来源的结论           |
| 学习者         | 阅读在线练习或考试题目、生成答案、自动回填后由用户核对并提交 |
| 知识工作者     | 跨网页收集资料、查询事实、填写表单或完成后台操作             |
| 运营与行政人员 | 在 CRM、ERP、问卷或内容后台中执行重复点击和录入流程          |

共同特征：用户全程在场，浏览器是用户自己的工作现场，Agent 是可监督的协作者，不是无人值守的
机器人。

## 5. 核心产品概念与业务规则

### 5.1 核心概念

| 概念           | 定义                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 问学浏览器     | 用户直接启动和使用的 Chromium AI 工作浏览器，不再以外部浏览器启动器作为主要产品表面 |
| 问学账号控制域 | 保存问学登录、任务目录、模型配置、快捷入口和应用设置的账号级控制资料                |
| 任务浏览器资料 | 一个任务独占的持久化浏览器资料，保存网站 Cookie、登录态、权限、历史与站点存储       |
| 任务           | 用户创建的通用工作空间，是左侧任务列表中的一项                                      |
| 任务标签集合   | 归属于某个任务的一个或多个网页标签页；创建任务时初始只有一个问学新标签页            |
| AI 会话        | 任务内与问学 AI 的对话上下文；新建 AI 会话不会创建新任务，也不会清空任务标签页      |
| Agent 运行     | AI 会话中一次执行中的网页操作过程，可处于运行、等待用户、暂停、完成或失败状态       |
| 问学新标签页   | 新任务和普通新标签页的默认起点，提供搜索与网站快捷入口                              |

### 5.2 业务规则

1. 任务是用户可见的最高层工作单位，系统不得自动创建用户可见的子任务。
2. Agent 可以在内部形成执行计划和步骤，但这些步骤始终归属于原任务。
3. 新建任务时，系统创建一个独立任务并在其中打开一个问学新标签页。
4. 在当前任务内新建标签页只增加该任务的标签页，不创建新任务。
5. 每个浏览器标签页同一时刻只能归属于一个任务。
6. 每个任务独立保存标签页集合、当前标签页、AI 会话与 Agent 状态。
7. 每个任务拥有独立持久化的任务浏览器资料；Cookie、网站登录态、HTTP cache、LocalStorage、
   IndexedDB、Service Worker、网站权限、浏览历史、密码与 Session Restore 不得跨任务共享。
8. AI 会话与任务是不同概念。用户可以在同一任务内开始新会话，同时保留当前标签页集合。
9. Agent 默认只能感知和操作当前任务的标签页，不得跨任务访问。
10. 每个任务拥有独立 Agent 运行状态；P0 至少支持两个任务的 Agent 同时运行。切换任务不自动
    暂停后台 Agent，停止、等待用户、暂停和恢复只作用于对应任务。
11. 后台 Agent 不得抢占当前任务的窗口焦点或可见标签；需要登录、验证码、权限或其他人工接管时，
    只暂停对应任务并在任务列表中通知用户。
12. 问学登录 session、任务目录、自定义模型配置、快捷入口和用量缓存属于账号控制域，可供该问学
    账号的任务使用；网站身份和浏览数据始终属于单个任务浏览器资料，不得因此共享。

## 6. P0 功能需求

### F1. 问学浏览器启动与工作台

#### 用户故事

作为用户，我希望直接打开问学浏览器并进入上次的工作状态，而不是先打开启动器再启动另一个浏览器。

#### 需求

- 问学以独立浏览器应用启动。
- 登录成功后进入浏览器工作台；未登录用户只能进入登录与注册流程。
- 工作台提供左侧任务入口、顶部浏览器导航能力、网页内容区域和问学 AI 入口。
- 浏览器重启后恢复任务列表、每个任务的标签页集合和上次活动位置。
- 异常崩溃后允许恢复未正常关闭的任务与页面。

#### 验收标准

- 当已登录用户启动问学时，系统应直接恢复其最近一次浏览器工作状态。
- 当未登录用户启动问学时，系统应阻止进入工作台并提供用户 id 与密码登录或注册入口。
- 当浏览器异常退出后再次启动时，系统应提供恢复上次任务和标签页的能力。
- 当用户进入工作台时，系统应提供左侧任务区、顶部地址与搜索栏和右上角问学 Logo；颜色、尺寸、
  动效和组件样式留给 UIUX。

### F2. 通用任务管理

#### 用户故事

作为用户，我希望用任务组织不同工作，同时让每个任务保留自己的网页和 AI 上下文。

#### 需求

- 用户可以新建、切换、重命名、关闭和删除任务。
- 新建任务后立即进入该任务的问学新标签页。
- 关闭任务不等于删除任务；关闭后的任务应可从历史中恢复。
- 删除任务前必须二次确认，并明确告知会删除的标签页状态与本地 AI 会话记录。
- 任务列表展示足以区分任务的名称、最近活动时间和 Agent 状态。
- 系统可以建议任务名称，但用户始终可以修改。
- Agent 的内部规划不得生成新的用户可见任务。

#### 验收标准

- 当用户点击新建任务时，系统应创建唯一任务并在该任务内打开问学新标签页。
- 当用户切换任务时，系统应恢复目标任务的标签集合、当前标签页和 AI 会话。
- 当 Agent 将用户指令拆解为多个步骤时，系统应仍只保留一个用户可见任务。
- 当用户关闭并恢复任务时，系统应恢复关闭前的标签页和 AI 上下文。
- 当用户删除任务时，系统应先取得明确确认且不得误删其他任务数据。
- 当用户切换离开正在运行 Agent 的任务时，该 Agent 应在不抢占前台的前提下继续运行；切回任务时
  应展示其当前标签、过程和状态。

### F3. 浏览器基础功能

#### 用户故事

作为用户，我希望问学可以承担 research、答题和网页操作所需的正常浏览，而不必切回其他浏览器。

#### 需求

- 顶部地址与搜索栏同时支持 URL 访问和搜索关键词。
- 支持后退、前进、刷新、停止加载和回到新标签页。
- 支持在当前任务内新建、切换、关闭、重新打开和调整标签页顺序。
- 支持查看当前任务的基础浏览历史并从历史记录重新打开网页。
- 用户点击在新标签页打开的链接时，新标签页归属于当前任务。
- 支持网页下载、下载进度、打开下载文件和定位下载目录。
- 支持网页文件选择与上传、剪贴板、页面内查找、页面缩放和全屏。
- 支持常见网页、PDF、音视频和浏览器错误页的正常显示。
- 支持网站 Cookie、登录态、缓存和授权结果在当前任务内持久化，且不得出现在其他任务中。
- 对摄像头、麦克风、通知、位置、剪贴板及弹窗等权限提供明确的允许或拒绝流程。
- 对证书错误、网络错误和页面崩溃提供可理解的错误信息与恢复动作。

#### 验收标准

- 当用户在地址栏输入合法 URL 时，系统应在当前任务的当前标签页打开该地址。
- 当用户输入非 URL 文本时，系统应使用当前搜索引擎执行搜索。
- 当网页打开新标签页时，系统应把新标签页加入当前任务且不得加入其他任务。
- 当用户在任务 A 完成网站登录并重启浏览器时，系统应在任务 A 中保留登录态；新建或恢复任务 B
  时，同一网站不得自动获得任务 A 的登录态。
- 当网站请求敏感权限时，系统应在授权前展示来源与权限类型。

### F4. 问学新标签页

#### 用户故事

作为用户，我希望新任务和新标签页提供清晰的搜索起点与常用网站入口。

#### 需求

- 新建任务和当前任务内新建标签页时，默认打开问学新标签页。
- 新标签页提供搜索能力，并与顶部地址与搜索栏使用同一搜索引擎设置。
- 默认快捷入口至少包含百度、学习通和必应中国。
- 用户可以添加、编辑、删除和排序自定义快捷入口。
- 首次使用新标签页时提供可跳过且不重复打扰的基础 onboarding。
- 快捷入口和新标签引导数据保存在问学账号控制域中，不携带任何网站身份数据。
- 新标签页可以提供问学设置与使用帮助入口，但不替代右上角问学 Logo 的 AI 入口。

#### 验收标准

- 当用户创建新任务时，系统应显示可立即搜索和打开快捷入口的问学新标签页。
- 当用户修改快捷入口后重启浏览器时，系统应保留修改结果。
- 当用户从新标签页执行搜索时，系统应在当前任务内展示搜索结果。

### F5. 问学 AI 入口与侧边栏

#### 用户故事

作为用户，我希望在任意网页随时唤出问学 AI，并让 AI 自动理解当前任务和当前页面。

#### 需求

- 浏览器右上角提供固定的问学 Logo 入口，用于打开或收起问学侧边栏。
- 侧边栏属于当前任务；切换任务时同步切换到该任务的 AI 会话。
- 侧边栏收起后不得清空会话、停止任务或丢失执行状态。
- 侧边栏打开时，AI 可以获得当前任务、当前标签页和该任务标签集合的必要上下文。
- 用户无需选择 Research、答题或其他模式，直接输入自然语言任务。
- 侧边栏提供新建 AI 会话入口；新会话仅重置当前 AI 上下文，不创建新任务、不关闭标签页。
- 侧边栏继续保留模型快捷切换、设置、语言、历史和停止等现有入口。

#### 验收标准

- 当用户点击问学 Logo 时，系统应在不离开当前网页的情况下打开或收起侧边栏。
- 当用户切换任务时，系统应显示目标任务的 AI 会话，不得串入其他任务的上下文。
- 当用户在同一任务中新建 AI 会话时，系统应保留该任务全部标签页。
- 当侧边栏收起后再次打开时，系统应恢复收起前的会话与 Agent 状态。

### F6. 现有问学插件能力等价迁移

功能等价基线冻结为 extension 1.9.1、仓库提交
8a29557797e9ffbbc7fbe1d88de463529c6f0820 的插件与 vendor 代码。迁移项目必须建立能力等价矩阵，
记录每个能力 ID 的旧版测试页面、模型配置、自动化或人工用例、新版结果与证据。以下能力均为 P0，
不得在浏览器化迁移中删除或弱化。

| ID     | 能力组     | 必须保持的行为                                                                           |
| ------ | ---------- | ---------------------------------------------------------------------------------------- |
| CAP-01 | 对话体验   | 自然语言输入、流式过程反馈、Markdown 结果、错误内联提示、任务完成后的继续追问            |
| CAP-02 | Agent 循环 | DOM 文本化、LLM 决策、工具执行、结果反馈和循环直至完成或需要用户                         |
| CAP-03 | 页面动作   | 点击、输入、选择、滚动、页面读取、遮罩、高亮和模拟光标反馈                               |
| CAP-04 | JavaScript | isolated 与 main world 执行、目标 frame 选择、错误与超时处理；默认启用且可在高级设置关闭 |
| CAP-05 | 多标签     | 新建、切换、关闭、等待加载、跨页接续、浏览器视图跟随当前任务内的 Agent                   |
| CAP-06 | Frame      | 发现 frame 元数据并在允许的目标 frame 中读取或执行操作                                   |
| CAP-07 | 视觉观察   | Agent 自主调用当前可见视口截图，视觉模型返回结构化观察；图片本体不持久化                 |
| CAP-08 | 会话上下文 | 同会话续接、体积压缩、摘要、近上限提醒、最旧步骤淘汰与历史步骤取回                       |
| CAP-09 | 历史       | 本地保存、任务内恢复、查看步骤、继续追问、导出和清理                                     |
| CAP-10 | 用户协作   | 缺失信息时提问并续接；停止、等待、暂停、恢复、登录或验证码接管后的继续执行               |
| CAP-11 | 模型配置   | 内置模型、自定义 OpenAI-compatible 模型、模型切换、语言与高级选项                        |
| CAP-12 | 日志与用量 | 统一日志、脱敏、查询、导出、保留策略和 tokens 统计                                       |
| CAP-13 | 学习通     | 读取题目、生成结构化答案、自动回填、翻页和汇总；绝不自动提交                             |

#### 验收标准

- 当相同测试页面和模型配置分别运行在旧插件基线与新浏览器中时，新浏览器应通过全部功能等价用例。
- 当能力等价矩阵中的任一 CAP ID 缺少旧版基线、预期结果或新版验证证据时，该能力应视为未通过。
- 当任一 P0 能力尚未通过等价验证时，浏览器化迁移不得被标记为完成。
- 当迁移改变内部实现时，用户可见行为、数据完整性和安全边界应保持不低于旧插件基线。

### F7. 任务内多标签 Agent

#### 用户故事

作为用户，我希望给出一个通用任务后，Agent 可以自行使用当前任务中的多个网页完成工作，而不会
干扰其他任务。

#### 需求

- Agent 可以在当前任务内打开、切换、关闭和读取多个标签页。
- Agent 创建的标签页自动归属于发起 Agent 的任务。
- 用户在当前任务手动创建的标签页也属于该任务，并可被 Agent 在权限允许时使用。
- 当前任务的 Agent 切换标签页时，浏览器视图跟随到当前操作页面；后台任务 Agent 不得抢占当前
  可见页面，用户切回该任务时应看到其当前操作标签。
- Agent 可以跨标签页保持同一任务和 AI 会话上下文。
- Agent 不得枚举、读取、激活或操作其他任务的标签页。
- 用户切换离开正在运行 Agent 的任务时，该 Agent 默认继续运行；用户可以从任务列表单独暂停、
  停止或恢复它。
- P0 至少支持两个任务同时运行 Agent；每个 Agent 使用自己任务的标签、网站身份、AI 会话和运行
  状态，任一任务失败或等待用户不得暂停其他任务。
- 后台任务需要视觉表面而无法安全取得时，只把该任务置为“等待前台”，不得激活标签或切换当前
  用户任务。
- 特权页、受限页面、sandbox、CSP、跨域 frame 和验证码等限制继续返回结构化错误或人工接管提示。

#### 验收标准

- 当 Agent 在任务 A 中打开多个标签页时，所有新标签页应只出现在任务 A。
- 当任务 B 同时存在时，任务 A 的 Agent 应无法读取或操作任务 B 的标签页。
- 当 Agent 在当前任务内切换页面时，系统应展示 Agent 实际操作的标签页。
- 当任务 A 与任务 B 的 Agent 同时运行时，两者应分别操作自己的标签与网站身份，且任务 A 的前台
  切换、暂停、失败或人工接管不得改变任务 B 的运行状态。
- 当 Agent 遇到不可操作页面时，系统应保留上下文并提供人工接管或替代路径。

### F8. AI 会话、上下文与历史

#### 用户故事

作为用户，我希望长任务可以连续追问、暂停恢复，并在以后重新打开任务继续工作。

#### 需求

- 任务完成或失败后，用户在同一会话继续输入时默认续接上下文。
- 新建 AI 会话是显式上下文边界，但不影响任务标签页。
- 历史上下文按体积自动压缩，保留用户原始指令和最近步骤。
- 早期步骤的原始记录继续保存在本地历史，可按需取回。
- 接近模型上下文上限时提供非模态提示，用户可以继续当前会话。
- 同一会话的多轮续接在历史中保持为一条连续记录。
- 用户可以从历史恢复可继续的 AI 会话。
- 用户可以查看、导出和删除历史；导出文件使用问学品牌前缀。

#### 验收标准

- 当用户在完成后的同一会话继续输入时，系统应保留上一轮有效上下文。
- 当用户新建 AI 会话时，系统应清空提示词上下文但保留当前任务标签页。
- 当历史接近模型上限时，系统应继续执行压缩策略而不是直接中断任务。
- 当用户恢复历史会话时，系统应允许继续追问且不得串入其他任务历史。

### F9. 学习通与答题能力

#### 用户故事

作为用户，我希望在学习通或标准 HTML 题目页面让问学读取题目、生成答案并回填，由我最终核对和提交。

#### 需求

- 学习通能力继续作为通用 Agent 可调用的专项工具，不要求用户切换答题模式。
- 支持学习通作业与考试页面的当前页和全部页两种处理范围。
- 等价迁移范围包括单选、多选、判断、填空、连线、完形填空、阅读理解及其子题。
- 支持识别、读取和序列化题干、选项、空位、子题、公式与图片内容。
- 文本题使用文本模型，含图题使用视觉模型；缺少所需模型时标记人工复核。
- 支持调用模型生成结构化答案，并按题目和选项标识精确回填。
- 未知题型、空题干、模型失败、结构不合法或低置信度结果标记 needsReview，不盲目回填。
- 全部页范围支持自动翻页、页数上限保护、中断和最终汇总。
- 系统不得自动点击最终提交、交卷或确认按钮。
- 系统不得绕过登录、验证码、人脸识别、字体反爬或其他平台防护。
- 对无法可靠识别或低置信度的题目提示用户检查。

#### 验收标准

- 当用户在学习通作业或考试页面提出当前页或全部页任务时，系统应按所选范围处理并返回题数、
  成功回填数、需人工复核数和页数汇总。
- 当题型属于单选、多选、判断、填空、连线、完形填空或阅读理解时，系统应执行对应的结构化生成
  与回填等价用例。
- 当题目含图片时，系统应使用视觉模型；视觉模型不可用或结果不可靠时应标记人工复核。
- 当页面出现最终提交动作时，系统应停止自动操作并由用户决定是否提交。
- 当页面防护阻止读取或操作时，系统应提示人工处理而不是尝试绕过。

### F10. 用户账号、模型与网关

#### 用户故事

作为用户，我希望登录问学后直接使用内置模型，也可以配置自己的 OpenAI-compatible 模型。

#### 需求

- 问学提供用户 id 与密码注册和登录，不要求短信、邮箱验证码或第三方 OAuth。
- 注册成功后，新用户默认获得内置模型使用权限；后台管理员可以随后禁用。
- 登录成功后进入浏览器工作台，用户会话用于内置模型网关鉴权与云端 tokens 汇总。
- 浏览器在 access token 到期前或到期后使用 refresh token 自动刷新 session；刷新失败时要求重新登录。
- 默认文本模型为内置 qwen3.7-max，默认视觉模型为内置 qwen3.7-plus。
- 视觉 / 多模态模型候选不得包含纯文本内置模型 qwen3.7-max；自定义模型仍可由用户按实际能力配置为
  主模型或多模态模型。
- 内置模型仅经问学 CloudBase LLM Gateway 调用，不保留客户端直连厂商的本地兜底；厂商 API Key
  不下发客户端。
- 网关在请求模型厂商前校验用户 session 与启用状态，被禁用用户不得产生厂商请求。
- 用户可以添加多个自定义模型，分别配置厂商、URL、API Key 和模型名。
- 自定义模型 API Key 只保存在本机问学账号控制域中，并使用 OS 密钥服务封装。
- 任务、AI 历史、自定义模型 API Key 和云端用量缓存按问学账号隔离；退出账号后不得向下一登录
  账号展示。
- 侧边栏模型入口显示当前主模型的实际模型名；展开后分别展示当前主模型与多模态模型候选，并允许在任务开始前
  快捷切换任一角色。侧边栏与插件设置页共享同一份持久配置，一处更改后另一处必须同步，下一次可用的
  Agent 请求必须使用新配置；Agent 运行中禁止切换，外部设置变更在当前任务结束后生效。
- 会话过期、用户被禁用或无权限时，在 AI 会话中提供明确错误与重新登录指引。

#### 验收标准

- 当已登录且有权限的用户首次使用内置模型时，系统应无需填写厂商 API Key 即可执行任务。
- 当用户配置有效的自定义模型时，系统应允许选择并执行任务。
- 当用户打开视觉 / 多模态模型选择时，候选中不得出现内置 qwen3.7-max；当用户分别从设置页或
  侧边栏切换主模型 / 多模态模型时，另一处应显示同一选择，随后创建的 Agent 应使用对应模型。
- 当用户 session 失效时，系统应阻止内置模型请求并引导重新登录。
- 当新用户完成注册与登录时，系统应允许其直接使用内置模型，除非管理员已禁用。
- 当管理员禁用用户时，网关应在联系模型厂商前拒绝该用户的下一次内置模型请求。
- 当同一问学安装先后登录两个问学账号时，后登录账号应无法读取前一账号的任务、AI 历史、
  自定义模型 API Key 和用户级用量缓存。
- 当记录日志和用量时，系统不得写入 API Key、access token、refresh token 或敏感鉴权头。

### F11. 数据持久化与迁移

#### 用户故事

作为现有问学用户，我希望升级到新浏览器后保留必要的模型设置、会话历史和网站登录状态，不发生静默丢失。

#### 需求

- 任务、标签集合、AI 会话、快捷入口、模型设置、日志配置和本地历史按问学账号保存，并可跨浏览器
  重启保留。
- 每个任务使用独立持久化的任务浏览器资料；网站身份、站点存储、权限、历史和 Session Restore
  不得跨任务共享。
- 删除单个任务只删除该任务的浏览器资料和任务 AI 数据，不得删除其他任务或问学账号控制域。
- 从现有启动器与插件升级时，系统应枚举已有浏览器画像并让用户选择 P0 的主迁移来源，不得静默
  假定某个画像。
- P0 迁移所选画像中的兼容数据；未选择或暂不支持迁移的画像保持原样，并提供数据清单与后续导出
  或迁移路径。
- 迁移前应识别数据版本；迁移失败时保留原数据并提供可恢复错误。
- API Key 和用户 session 的迁移继续遵守本地与敏感数据边界。

#### 验收标准

- 当用户正常退出并重新启动浏览器时，系统应恢复任务、标签页和 AI 会话。
- 当现有用户首次启动新浏览器时，系统应迁移兼容数据或明确说明无法迁移的项目。
- 当检测到多个现有画像时，系统应要求用户选择主迁移来源，并在迁移前列出其他画像的保留状态。
- 当迁移发生错误时，系统应保留原始数据且不得以空数据覆盖。
- 当用户删除任务时，系统应删除该任务的网站登录态并完整保留其他任务各自的网站登录态。

### F12. 日志、审计与 Tokens

#### 用户故事

作为用户，我希望查看 Agent 做过什么、为什么失败以及消耗了多少 tokens。

#### 需求

- 统一记录浏览器、AI 侧边栏、Agent、标签页操作、学习通、配置和 LLM 调用日志。
- 日志支持按级别、来源、任务、时间和关键词筛选。
- 日志支持实时查看、暂停跟随、查看详情、导出和清空。
- 日志默认保留 3 天且最多 5000 条，两项均可由用户调整；超期或超量时按最旧优先清理。
- LLM 请求与响应正文仅允许在本机按现有规则脱敏保存。
- API Key、Authorization、Bearer、access token 和 refresh token 永不进入日志。
- tokens 页面展示输入、输出、总量、模型、日期、任务归因和估算成本。
- 新浏览器以任务归因替代旧启动器的浏览器画像归因；迁移后的历史画像数据保留其原来源标记。
- tokens 聚合总数必须等于明细求和，成本估算规则可由用户查看，无数据时提供空状态与下一步说明。
- 云端网关计量优先，本地脱敏记录或当前问学账号的缓存作为不可用时的兜底。
- 仅本机调试日志可以按现有规则保存已脱敏的 LLM 请求与响应正文。
- 本地和云端 tokens 记录、网关计量及后台响应一律不得包含提示词或模型响应正文。
- 所有日志、tokens、计量、缓存和后台响应均不得包含 API Key、Authorization、Bearer、
  access token 或 refresh token。

#### 验收标准

- 当 Agent 在任务中执行时，用户应能按任务查看相关日志与 tokens。
- 当用户导出日志时，导出内容应遵守当前筛选条件和脱敏规则。
- 当云端用量不可用时，系统应显示同用户缓存或本地兜底，并说明数据来源。
- 当存在多日、多模型和多任务明细时，系统展示的各维度总量应与明细求和一致。
- 当没有用量数据时，系统应显示空状态；当显示估算成本时，应允许用户查看估算规则。
- 当输入含敏感凭据时，脱敏测试应证明凭据不会进入持久化日志。
- 当检查本地和云端 tokens 数据时，系统应证明其中不含提示词或模型响应正文。

### F13. 安全、合规与人工接管

#### 需求

- 问学定位为用户在场的协作助手，不是无人值守网页机器人。
- 用户可在任何 Agent 运行阶段停止任务。
- 仅当任务因缺少必要的用户专属信息或存在无法从页面判断的歧义选项而无法继续时，Agent 才调用 `ask_user`；回答返回同一次工具调用并继续原任务。
- Agent 遇到登录、验证码、权限确认、支付、删除、提交、交卷或模型重复动作时，进入人工接管。
- 登录、验证码、滑块验证、2FA 与权限确认不得通过普通提问索取值；Agent 应立即展示人工接管提示并停止后续自动操作。
- Agent 暂停或等待用户时保留任务、会话和标签页上下文。
- 停止任务、重置会话、替换 Agent 或任务 AbortSignal 触发时，必须取消待回答问题与待接管请求，旧回答不得进入后续任务。
- 视觉截图只用于单次视觉模型请求，图片本体不写入历史、日志或持久化存储。
- 自定义模型的页面数据只发送到用户明确配置的模型端点。
- 不开发验证码绕过、防作弊反检测、指纹伪装或自动提交能力。
- AI 生成内容应向用户提供持续可见的 AIGC 标识。

#### 验收标准

- 当用户点击停止时，系统应停止后续 Agent 动作并保留可查看历史。
- 当两个任务的 Agent 同时运行且用户停止其中一个时，另一个任务应继续运行。
- 当任务缺少必要信息时，侧边栏应展示一个明确问题、解锁回答输入，并在用户回答后继续同一任务。
- 当页面需要用户完成敏感步骤时，系统应停止自动操作并明确说明下一步。
- 当登录或验证码页面出现时，系统应展示人工接管提示，不得退化为普通 `ask_user` 问题。
- 当用户在等待回答时停止或重置任务，原问题 Promise 应取消且其后到达的回答不得恢复旧任务。
- 当视觉观察完成时，系统应确认截图本体未进入持久化数据。
- 当 Agent 连续重复同类动作达到产品阈值时，系统应停止循环并请求用户处理。

### F14. 性能、可靠性与平台

#### 需求

- P0 支持 macOS Apple Silicon 与 Windows x64。
- 从双击应用到浏览器可用应不超过 10 秒，不含首次系统授权和版本更新。
- 性能基线至少包含 Speedometer、JetStream 和 MotionMark；每次发布记录实际使用的基准版本。
- 基准对比使用相同 OS、设备、Chromium 版本和相同数量的干净隔离 Profile，每项预热后运行至少
  5 次并取中位数。
- 核心 Web 性能基准中位数不低于对应 Chrome for Testing 的 95%。
- 单任务典型 10 标签页集合的稳定内存占用不高于单 CfT Profile 基线的 115%；两个任务各 5 个标签
  的并行场景不高于两个隔离 CfT Profile 对照的 115%。
- 浏览器与 AI 均空闲 5 分钟时，问学进程组 CPU 中位数不高于 CfT 基线 1 个百分点。
- AI 未运行时不得持续执行 DOM 扫描、页面截图或 Agent 轮询。
- AI 空闲状态的页面加载和标签切换耗时中位数不高于 CfT 基线的 110%。
- 浏览器异常退出后可恢复任务和标签页，不产生持续僵尸状态。
- 连续启动和退出 10 次不得遗留不可回收的浏览器进程。
- 对外公开分发前必须具备 Chromium 安全版本更新机制；内部原型可暂用人工升级。
- 浏览器升级不得静默破坏问学 AI 功能或用户数据，发布前必须运行功能等价与数据迁移回归。

#### 验收标准

- 当在目标平台执行启动与退出稳定性测试时，系统应满足时间、状态恢复和无残留进程要求。
- 当按固定条件执行同版本基准测试时，问学浏览器应同时满足 Web 性能、单任务与双任务内存、相同
  Profile 数量下的空闲 CPU、页面加载和标签切换阈值。
- 当问学 AI 处于空闲状态时，系统应不存在持续 DOM 扫描和截图活动。
- 当浏览器内核升级时，发布门禁应覆盖全部 P0 插件等价能力。

## 7. 配套系统需求（延续）

本次浏览器化不取消现有 CloudBase LLM Gateway、后台管理、官网和 tokens 计量的产品目标，但不在本
轮重新设计其 UI 或技术实现。

### F15. CloudBase LLM Gateway

- 用户注册成功后创建同一 uid 的启用记录，新用户默认可调用内置模型。
- 使用 CloudBase 用户 session 鉴权内置模型请求。
- 请求模型前解析用户 uid 并校验启用状态，禁用用户在联系模型厂商前被拒绝。
- 厂商 Key 仅存服务端环境变量。
- 流式透传模型响应并按用户 uid 记录不含正文和敏感凭据的 tokens 用量。
- 网关不得持久化提示词或模型响应正文。
- 提供当前用户脱敏用量汇总。

### F16. 后台管理

- 内部管理员通过 CloudBase Auth 账号登录。
- 管理员可查看 tokens 汇总、用户列表及启用状态。
- 管理员可启用或禁用用户的内置模型权限。
- 每次权限调整写入审计记录。
- 后台不得展示提示词正文、模型响应正文、API Key 或用户 session。

### F17. 官网

- 官网继续承担产品说明、下载、文档和演示入口。
- 新浏览器公开发布后，官网应提供对应平台下载与版本说明。
- 官网具体视觉与页面结构不属于本轮 PRD。

## 8. P0 端到端链路

### 8.1 通用多标签任务

1. 用户启动问学并登录。
2. 用户新建任务，系统打开问学新标签页。
3. 用户通过新标签搜索或在顶部地址与搜索栏输入地址。
4. 用户浏览目标网页，点击右上角问学 Logo 打开侧边栏。
5. 用户输入一个通用自然语言任务。
6. Agent 在当前任务内读取页面，并按需要打开和切换多个标签页。
7. 用户观察执行过程，必要时停止、暂停或人工接管。
8. Agent 完成后返回结果，用户可以继续追问。
9. 用户切换到其他任务，再切回时恢复原任务的标签页和 AI 会话。

### 8.2 答题任务

1. 用户在当前任务访问学习通或标准 HTML 题目页面。
2. 用户打开问学侧边栏并要求读取、求解和回填。
3. Agent 读取题目，调用模型生成结构化答案并回填支持题型。
4. 遇到低置信度、验证码或页面限制时请求用户处理。
5. Agent 在最终提交前停止，由用户核对并决定是否提交。

### 8.3 升级迁移

1. 现有用户首次启动问学浏览器。
2. 系统识别已有启动器、插件数据版本和全部浏览器画像。
3. 存在多个画像时，用户选择 P0 的主迁移来源。
4. 系统把所选旧画像的网站数据迁入一个明确标记来源的导入任务 Profile，并迁移兼容的模型配置、
   历史和快捷入口；其他新任务保持干净隔离。
5. 对未选择或无法迁移的数据给出保留状态与明确清单，不静默丢弃。
6. 迁移失败时保留原数据并允许重试或导出。

### 8.4 隔离任务并行运行

1. Agent 在任务 A 中运行。
2. 用户切换到任务 B 并启动另一个 Agent。
3. 任务 A 在后台继续运行，但不得抢占任务 B 的窗口焦点或可见标签。
4. 两个 Agent 分别使用独立的任务浏览器资料、标签、AI 会话和运行状态。
5. 任一任务需要人工接管时，只暂停并通知该任务；用户切回后可以继续，另一任务不受影响。

## 9. P0 发布门禁

| 门禁           | 通过条件                                                              |
| -------------- | --------------------------------------------------------------------- |
| 浏览器基础能力 | F1–F4 全部验收通过                                                    |
| 插件功能等价   | CAP-01 至 CAP-13 均具备冻结基线与新版证据，无已知 P0 功能降级         |
| 多任务隔离     | 标签、Cookie、登录态、站点存储、权限、历史与 Agent 状态跨任务泄漏为 0 |
| 并行任务       | 至少两个任务 Agent 可同时运行，切换、暂停、失败与接管互不影响         |
| 账号隔离       | 同一问学安装中不同问学账号无法互读账号级本地数据                      |
| 数据迁移       | 多画像可选择来源，未选数据保留，迁移不静默丢失且失败可恢复            |
| 日志与用量     | 聚合可对账，正文与凭据边界、保留策略和同账号缓存回退全部通过          |
| 安全与隐私     | 凭据脱敏、截图不落盘、敏感动作人工接管全部通过                        |
| 性能           | Web、10 标签内存、空闲 CPU、页面加载和标签切换全部满足 F14 阈值       |
| 稳定性         | 双端连续启动和退出 10 次无残留进程或不可恢复状态                      |
| 真实场景       | research 与答题场景各连续演练 3 次，至少 2 次完整成功                 |

## 10. 非目标

P0 明确不做：

- Research、答题或其他固定任务模式选择。
- 自动把一个用户任务拆成多个用户可见任务。
- 脱离本机浏览器运行的云端无人值守任务、定时任务与跨设备任务执行；用户主动启动的本机并行任务
  属于 P0。
- 在任务之间共享或同步 Cookie、网站登录态、站点存储、权限、历史或密码。
- 任务间独立 OS 进程、虚拟机或文件系统沙箱；P0 的隔离边界是独立持久化 Chromium
  Profile/BrowserContext，仍共享浏览器程序、GPU/网络基础进程和本机文件系统。
- Chrome 账号登录与 Chrome Sync。
- Chrome Web Store 和任意第三方扩展安装。
- 完整书签管理、主题市场与消费级浏览器个性化。
- 将问学设为系统默认浏览器。
- Linux、Windows ARM64 与移动端。
- 订阅、扣费和账单出具。
- 验证码绕过、防作弊反检测、浏览器指纹伪装和自动提交。
- 本轮 UI 视觉、动效、尺寸、布局细节和组件规范。
- 本 PRD 不承载 Chromium、CEF 等具体内核路线论证；已批准技术路线以
  [目标架构](../02-design/ARCHITECTURE.md) 和 [架构决策](../02-design/DECISIONS.md) 为准。

## 11. 成功指标

- CAP-01 至 CAP-13 能力等价矩阵通过率 100%，且每项均有冻结基线与新版验证证据。
- 多任务隔离测试中跨任务标签、Cookie、登录态、站点存储、权限、历史和扩展任务数据泄漏次数为 0。
- 至少两个任务的 Agent 可并行完成独立测试流程，任一任务暂停、停止或等待用户不影响另一任务。
- 用户可以在不离开问学浏览器的情况下完成 research 和答题示例流程。
- research 与答题场景连续 3 次演练至少 2 次全链路成功。
- 从启动应用到浏览器可用不超过 10 秒。
- 从用户提交 AI 指令到 Agent 开始第一个网页动作不超过 60 秒，含必要的模型连接。
- 同版本核心 Web 性能、10 标签内存、空闲 CPU、页面加载和标签切换全部满足 F14。
- API Key、Authorization、Bearer、access token、refresh token 和视觉截图持久化泄漏为 0。

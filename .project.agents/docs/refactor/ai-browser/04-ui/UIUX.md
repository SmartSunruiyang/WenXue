# AI 浏览器 UI/UX 约束与统一设计入口

> **已废弃（2026-09-25）：** 按用户决定，Chromium AI 浏览器重构方案停止执行。本文件是废弃前历史快照，不代表当前产品现状，也不得作为后续任务或实施依据。当前产品以[当前 PRD](../../../context/PRD.md)为准，发布工作见[桌面发布与通知计划](../../../superpowers/plans/2026-09-25-desktop-release-notifications-updates.md)。

> 状态：功能不变量保持；2026-09-18 用户已批准跨端统一视觉。
> 唯一视觉正文：[问学 UI 设计指导](../../../context/UIUX.md)。

## 1. 当前目的

本文定义目标 Chromium 的任务、隔离与交互不变量；颜色、字体、布局语言、控件、动效与可访问性直接引用统一规范，不维护独立色板。此次视觉统一不改变 Chromium 实施阶段或数据边界。

## 2. 产品信息架构不变量

- 产品默认呈现为一个问学工作浏览器/工作台。
- 左侧是任务列表，用户可新建、选择、命名和管理通用任务。
- 新建任务后，主区域打开该任务的问学新标签页。
- 主区域上方具备浏览器基础导航与 Omnibox/搜索能力。
- 主区域展示当前任务自己的 TabStrip；不同任务的标签页不混排。
- 问学新标签页提供网站快捷入口和搜索入口。
- 右上角问学 Logo 是唤起/收起问学 AI 侧边栏的稳定入口。
- AI 侧边栏始终绑定当前任务和当前任务内的浏览上下文。
- Research、答题、写作等是任务里可完成的工作，不是创建任务时必须选择的任务类型。
- 首版必须完整承接现有插件能力，包括多标签页 Agent。

## 3. 任务切换

用户从任务 A 切换到任务 B 时：

- 主区域展示 B 的标签页、地址与导航状态；
- AI 侧边栏切换到 B 的会话和运行状态；
- A 的页面、登录态、标签页和 Agent 状态保持在 A 内；
- A 的后台 Agent 可以继续运行；
- A 不得自动抢回焦点、切换前台任务或激活其标签页；
- A 需要用户确认、登录或前台交互时进入 waiting_foreground；
- UI 应提示 A 正在等待，但由用户决定何时切回；
- 切回 A 后恢复其上次可见标签页和侧边栏状态。

## 4. 多任务并行反馈

至少表达以下状态语义，使用统一规范的状态点 / 标签 / 原位反馈：

- idle：无运行；
- running：Agent 正在工作；
- waiting_foreground：需要用户切换到该任务处理；
- waiting_permission：等待明确授权；
- completed：本次运行完成；
- failed：运行失败，可查看原因或重试；
- paused/stopped：由用户暂停或停止。

状态必须按任务展示，不能用一个全局 loading 覆盖所有任务。停止、重试或关闭一个任务时，操作对象必须明确，不能误伤其他任务。

## 5. 浏览器基础交互

目标浏览器必须提供用户熟悉的基础能力：

- 地址输入、搜索建议与搜索提交；
- 后退、前进、刷新/停止；
- 新建、关闭、切换、重排和恢复标签页；
- 网站权限、下载、证书错误和弹窗的可理解反馈；
- 键盘导航与常用快捷键；
- 页面加载、失败、离线和崩溃状态；
- 当前任务、当前标签页和当前 AI 上下文的清晰归属。

具体与 Chromium 默认 UI 的保留、替换或品牌化程度，需通过后续设计与可用性验证决定。

## 6. 窗口模型约束

底层 TaskBrowserHost 可以为了 Chromium 原生语义使用内部 backing windows，但产品默认行为仍是一个工作台。

- 不默认为每个任务展示一个系统级浏览器窗口；
- 内部窗口不得出现在 Dock/任务栏、窗口切换器或用户可见的窗口管理中，除非平台限制经评审确认；
- 后台任务弹窗、权限和下载提示必须路由到所属任务；
- 内部承载方式不得造成焦点跳转、任务混淆或无障碍树断裂；
- 若平台确实需要暴露额外窗口，必须新增产品决策，不能由实现细节自行决定。

相关技术选择见 [ADR-006](../02-design/DECISIONS.md)。

## 7. AI 侧边栏边界

- 侧边栏只操作当前任务中的页面和标签页；
- 所有引用、截图、页面观察和操作结果标明所属标签页；
- 多标签页 Agent 可以在当前任务内新建、切换和关闭标签页；
- 请求访问另一个任务时必须被拒绝或要求用户显式切换，不自动跨任务执行；
- 任务切换期间未完成命令按 taskId 固定归属，不因 UI 当前选择变化而漂移；
- Agent 需要高风险操作、站点凭证或用户接管时，显示明确的任务/站点/run 作用域；
- 侧边栏关闭不等于停止 Agent，停止动作需单独、明确。

## 8. 统一视觉的应用

使用统一 UIUX 的白底、系统字体、黑色主操作、轻量分组与语义反馈。TabStrip、Omnibox 和任务栏具体承载尺寸在可运行外壳中验证，不能重新引入旧能量玻璃、彩色跑马灯或大范围页面编排。

## 9. 目标运行时验收补充

目标窗口仍需验证多任务归属、焦点、权限、下载和任务切换；既有 G1–G6 证据门禁不因视觉规范批准而提前完成。精确尺寸与原生浏览器控件融合在对应实现阶段通过跨平台可用性验收。

## 10. 功能验收

即使没有最终视觉稿，G2/G3 原型也必须证明：

1. 用户能在一个工作台创建并切换两个隔离任务；
2. 每个任务拥有自己的标签页、登录态和 AI 会话；
3. 两个 Agent 可以并行，后台任务不抢焦点；
4. waiting_foreground 能准确指向需要用户处理的任务；
5. Logo 可稳定唤起当前任务的问学侧边栏；
6. 新标签页、Omnibox、导航和标签页基础能力可用；
7. 用户始终能判断当前操作属于哪个任务和标签页；
8. 内部窗口机制不会泄漏成混乱的产品窗口模型。

## 11. 固定消息与更新中断面

- Chromium 消息与更新复用 [统一 UIUX §11](../../../context/UIUX.md#11-应用内消息与更新)，采用白底、中性系统字体与无侧轨的清晰正文布局。当前 Electron ready 后为“打开安装包”，Chromium G5 由正式签名 Updater 提供“重启并安装”。
- 后台只能提供标题、纯文本正文、可选 HTTPS 详情、重要性和目标；不得远端配置视觉、CTA 或关闭规则。
- 普通消息可由关闭/Escape/遮罩/“我知道了”确认；重要消息只允许按钮确认但可退出应用。消息回执
  属账号控制域，不进入 Task Profile。
- Chromium 可选更新只在用户点击后下载，ready 后显式重启安装；强制更新无“稍后”，但保留退出应用，策略
  离线超过 24 小时不得锁死工作区。
- 点击“重启并安装”后先显示策略复核状态；只有实时复核成功才进入安装。断网、pause/withdraw 或候选变化时停留在当前版本并提供重试，不以缓存 mandatory 策略继续安装。
- focus trap、`aria-modal`、焦点恢复、alert 语义和 reduced motion 为跨平台验收项；系统中断优先级为
  强制更新 > 重要消息 > 普通消息 > 可选更新。

# 问学 AI 浏览器重构文档体系

> - 状态：G0 产品与目标架构基线已批准，工程执行尚未开始
> - 建立日期：2026-07-14
> - 适用范围：问学从 Electron + Chrome for Testing 启动器迁移为 Chromium 内核 AI 工作浏览器

## 1. 目的

本目录是本次 AI 浏览器重构的唯一权威文档域，用于承载产品基线、目标架构、关键决策、基础设施要求、实施计划、迁移与验收证据。

重构目标不是把任务拆成 Research、答题等固定模式，而是提供通用任务容器：

- 用户从左侧创建任务；
- 每个任务拥有独立且持久化的浏览器环境；
- 创建任务后打开问学新标签页，并具备快捷入口、搜索、地址栏、导航和多标签页能力；
- 用户通过右上角问学 Logo 唤起 AI 侧边栏；
- 首版完整迁移现有问学 Chrome 插件能力，包括多标签页 Agent；
- 不同任务的登录态、站点数据、扩展状态和 Agent 运行域默认隔离，并可并行工作。

## 3. 权威性与冲突处理

同一问题只允许有一个正文权威来源，优先级如下：

1. PRD：用户行为、产品范围与验收结果；
2. ARCHITECTURE：模块边界、接口、数据、安全和运行时约束；
3. DECISIONS：已经批准的架构选择及其原因；
4. INFRASTRUCTURE：仓库、工具链、构建、发布、签名和安全运维；
5. UIUX：交互不变量与后续视觉规范；
6. PLAN：实施顺序、依赖与阶段出口；
7. READINESS、TESTING、MIGRATION：执行检查表与可审计证据。

若文档冲突：

- 先停止依赖冲突内容的实现；
- 修改上游权威文档并完成评审；
- 按“变更传播矩阵”同步下游文档；
- 在 DECISIONS 中记录会改变架构方向的选择；
- 不以聊天记录、代码注释或旧路径副本替代权威文档。

## 4. 与现有文档体系的边界

- .project.agents/docs/context/ 的工程文档继续描述当前 Electron + Chrome for Testing 运行时，是迁移完成前的现状权威来源；其中 PRD.md 已改为目标 PRD 的兼容指针。
- 本目录描述目标 Chromium AI 浏览器，是所有新重构工作的目标权威来源。
- 当前运行时发生变化时，更新 context 文档。
- 目标运行时发生变化时，更新本目录。
- 涉及兼容层、迁移桥或切换策略的变化，需要同时更新两侧文档。
- 旧 PRD、设计和计划路径仅保留兼容指针，不再维护正文。
- 全局工作日志仍按项目规则写入 .project.agents/log/；本目录不复制日志正文。

## 5. 变更传播矩阵

| 发生变化                              | 必须同步                                             |
| ------------------------------------- | ---------------------------------------------------- |
| 产品范围、用户流程、验收标准          | PRD → ARCHITECTURE → PLAN → TESTING                  |
| 任务隔离、凭证、安全边界              | ARCHITECTURE → DECISIONS → TESTING → MIGRATION       |
| Chromium 分支、工具链、仓库或构建方式 | INFRASTRUCTURE → READINESS → PLAN                    |
| 插件能力或接口迁移策略                | ARCHITECTURE → PLAN → TESTING → MIGRATION            |
| 数据格式、导入范围或回滚策略          | MIGRATION → ARCHITECTURE → TESTING → PLAN            |
| 交互不变量                            | UIUX → PRD → ARCHITECTURE → TESTING                  |
| 已批准关键选择被替代                  | DECISIONS 新增 superseded 记录，并同步所有受影响文档 |

## 6. 阶段门禁

| 门禁 | 目标                     | 必要证据                                                 |
| ---- | ------------------------ | -------------------------------------------------------- |
| G0   | 产品、目标架构与计划冻结 | PRD、ARCHITECTURE、PLAN 获批                             |
| G1   | Chromium 工程可重复构建  | 仓库与 revision 锁定、工具链就绪、macOS/Windows CI 产物  |
| G2   | 任务隔离骨架成立         | 两个任务独立 Profile、并行标签页、重启恢复、凭证边界验证 |
| G3   | 插件能力完整迁移         | 能力矩阵全量通过，多标签页 Agent 与并发任务验证          |
| G4   | 数据迁移与性能达标       | 迁移演练、回滚演练、对称性能基线、长稳测试               |
| G5   | 受控发布可用             | 签名、更新、安全响应、灰度与回滚链路验证                 |
| G6   | 旧运行时退场             | 稳定窗口结束、无阻断回滚事件、旧链路正式下线             |

任何阶段只有在对应证据可复现、可定位到构建和 revision 时才能通过。

## 7. 维护规则

- 文档使用相对链接，避免复制同一段规范到多个位置。
- 状态必须使用“草案、待评审、已批准、已废弃”或明确的阶段状态。
- 关键结论需带日期、责任域和验证方式。
- 实现任务必须引用对应需求、架构章节和测试项。
- 不在本目录存放临时构建输出、测试截图或二进制文件；证据应链接到受控位置。
- UI 视觉稿不在当前阶段提前固化；先保证功能、隔离、安全和迁移边界可验证。

## 8. 当前下一步

当前处于 Phase 0.3 / G1 前置就绪阶段。下一步不是直接修改 Chromium，而是先完成：

1. 确认目标 Chromium 仓库、可见性、访问方式与责任人；
2. 锁定目标 Chromium revision 和上游安全更新策略；
3. 补齐 macOS 与 Windows 构建机、工具链和存储方案；
4. 建立现有插件能力矩阵与 Chrome for Testing 对称性能基线；
5. 评审任务隔离 Spike、迁移样本和测试证据模板。

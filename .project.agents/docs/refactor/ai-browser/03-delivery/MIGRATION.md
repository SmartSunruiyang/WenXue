# 用户数据迁移与回滚规范

> - 状态：G2 前待评审
> - 最后更新：2026-08-07（同步 Electron 账号归属画像来源格式）
> - 目标：把用户明确选择的旧运行时数据导入一个独立问学任务，同时保持其他任务干净、原始数据不变且失败可回滚。

## 1. 核心原则

- 默认不迁移。只有用户明确选择来源和范围后才执行。
- 一次迁移只写入一个新建的导入任务，不把旧登录态复制到所有任务。
- 之后新建的其他任务仍是干净、隔离的浏览器环境。
- 未选择的旧 Profile、任务和数据保持原样。
- 不直接把运行中的旧 Profile 目录作为新任务目录使用。
- 迁移采用“只读源 → staging → 校验 → 原子激活”，失败不暴露半成品任务。
- 迁移可重试且具备幂等语义；原始数据在稳定窗口结束前不被破坏性修改。
- 加密凭证无法安全迁移时必须明确降级为重新登录，不绕过操作系统保护。

## 2. 范围

### 2.1 可选择迁移

- 书签与文件夹；
- 浏览历史；
- 指定站点的 Cookie/登录态，在平台加密与 Chromium 兼容条件允许时；
- 保存的密码和自动填充数据，在用户授权且 OSCrypt 兼容时；
- 站点权限；
- 下载记录，不复制下载文件本体，除非产品另行批准；
- 问学扩展配置、会话索引和允许迁移的任务元数据；
- 已打开标签页与窗口恢复信息；
- 用户明确选择的快捷入口和偏好。

### 2.2 默认不迁移

- 磁盘缓存、GPU 缓存、代码缓存；
- Service Worker 运行时缓存与临时 worker 状态；
- solver in-flight run / session effect ledger、tab mutation owner/quarantine、PendingControlJournal、
  EphemeralImageStore、ResultStore continuation token、独立 ResumeCursorStore token、
  logical/binding/question fingerprint、passive embedded candidate 与原始页面
  response；迁移后必须重新 probe 当前页面；
- 崩溃转储、临时文件和诊断日志；
- 浏览器主密钥、问学账号主令牌、刷新令牌或开发者密钥；
- 未识别扩展数据；
- 未被用户选中的其他旧 Profile；
- 跨操作系统账户无法验证所有权的加密数据。

### 2.3 Electron 旧画像来源与账号归属

迁移发现器必须区分两种来源格式：

- `electron-account-scoped-v1`：`<userData>/browsers.json` 的记录含 `accountNamespace`，Profile 仍位于
  `<userData>/profiles/<profileId>`。只有 `accountNamespace` 等于当前已验证问学账号的记录才可进入选择
  清单；当前账号必须由受信服务用 bearer token 解析真实 uid，不能信任 renderer 自报 userId；其他账号
  记录不得显示、读取、重归属或迁移。
- `electron-legacy-unowned-v0`：记录没有 `accountNamespace`，或只剩无法建立归属的 Profile 目录。目标
  迁移器不得自动把它归给当前账号；只有在独立的“无归属旧画像”风险提示、同一 OS 用户校验和用户
  明确选择后才可作为来源，且仍遵循只读源与 staging 流程。

发现器只信任经规范化后位于旧 `<userData>/profiles/` 根目录内的真实目录，不直接信任元数据中的任意
`userDataDir`。当前 Electron 运行时忽略 v0 记录，不提供认领 UI；上述 v0 选择仅属于目标 Chromium
迁移器能力。

## 3. 目标任务语义

迁移开始时创建带唯一 migrationId 的隐藏 staging 任务。成功激活后，它成为普通任务，例如“从旧版问学导入”。

- 导入任务拥有独立 user-data-dir；
- 其他已有任务不接收任何导入数据；
- 迁移完成后新建的任务保持全新 Profile；
- 导入任务可被用户删除，删除不影响旧运行时源数据；
- 导入任务的 Agent、扩展和站点数据遵循与其他任务相同的隔离规则。

## 4. 数据映射

| 旧数据                | 新目标                   | 策略                                                       | 失败降级                                               |
| --------------------- | ------------------------ | ---------------------------------------------------------- | ------------------------------------------------------ |
| Bookmarks             | 导入任务书签模型         | 使用 Chromium 支持的模型/API 导入并校验计数与层级          | 导出 HTML 供用户手动导入                               |
| History               | 导入任务 HistoryService  | 规范化 URL/时间后批量写入                                  | 跳过损坏记录并生成报告                                 |
| Cookies               | 导入任务 CookieStore     | 仅在格式、域、安全属性和加密可验证时导入                   | 要求重新登录                                           |
| Login Data            | 导入任务密码库           | 经用户确认，通过平台安全存储解密/重加密                    | 不复制，要求重新登录                                   |
| Autofill              | 导入任务 Autofill 数据库 | schema 转换与字段白名单                                    | 跳过不兼容字段                                         |
| Preferences           | 问学允许列表偏好         | 逐字段映射，不复制整个 Preferences 文件                    | 使用新默认值                                           |
| Permissions           | 导入任务 ContentSettings | 显式允许列表与过期策略                                     | 重新询问                                               |
| Tabs/Session          | 导入任务会话恢复         | 只迁移安全 URL 与顺序，不复用旧进程句柄                    | 显示可重新打开列表                                     |
| Extension storage     | 内置问学扩展存储         | 按 schema 版本执行迁移器                                   | 重置扩展设置并保留源备份                               |
| AI conversations      | 问学账号/本地会话索引    | 按数据所有权和服务协议迁移引用                             | 保留旧版可读或重新同步                                 |
| `chaoxing_solve` 历史 | 导入任务 AI history      | 原样保留只读工具事件；旧名称不注册到新 Agent，也不自动重放 | 通过新的 `visual_observe/question_solver` 调用重新运行 |
| Downloads history     | 导入任务下载记录         | 仅记录元数据并检查路径存在性                               | 标记文件缺失                                           |
| Cache/workers         | 不迁移                   | 新任务重新生成                                             | 无                                                     |

不得以“复制整个 user-data-dir”替代字段级策略，除非 Spike 证明选定 revision、平台和加密模型完全兼容，并得到独立安全评审。

## 5. OSCrypt 与凭证处理

Chromium 的 Cookie、密码和部分敏感数据依赖操作系统密钥链或 DPAPI。文件存在不代表新浏览器或新 OS 账户能够解密。

必须遵守：

- 只在同一受信操作系统账户内尝试解密；
- 使用 Chromium/平台提供的安全接口，不读取或记录明文主密钥；
- 解密后的敏感值只在受限进程内短暂存在，并立即用目标任务密钥重新加密；
- 迁移日志只记录数量、类别、错误码和哈希，不记录值；
- 跨设备、跨系统账户或算法不兼容时不迁移凭证；
- 用户取消、超时或授权失效后立即清理内存与 staging 数据；
- 无法证明安全性的情况统一要求用户在导入任务中重新登录。

## 6. 迁移流程

### 6.1 预检

1. 识别旧运行时版本、CfT revision、扩展版本、平台和 Profile，并按 §2.3 逐记录分类、规范化路径和过滤
   账号归属；
2. 确认旧浏览器完全退出或建立一致性快照；
3. 显示可迁移类别、风险、预计空间与重新登录提示；
4. 获取用户对来源、目标名称和数据范围的明确确认；
5. 检查磁盘、权限、密钥链访问和目标 schema；
6. 写入迁移 journal 的 planned 状态。

### 6.2 Staging

1. 创建全新隐藏任务目录和 manifest；
2. 把源数据以只读方式快照到受控临时区；
3. 按依赖顺序运行版本化迁移器；
4. 每个步骤写入开始、完成、输入摘要、输出摘要与错误；
5. 迁移器采用幂等键，重复运行不生成重复书签、历史或会话；
6. 敏感数据在写入后立即执行目标浏览器可解密验证。

### 6.3 校验

- 数据库完整性与 schema 版本；
- 各类别数量、关键字段和层级摘要；
- 目标任务可启动、浏览器服务可加载；
- 站点数据只存在于目标导入任务；
- 目标 `AccountNamespace` 与来源 owner 匹配，其他账号或未确认的无归属来源均未进入 staging；
- 其他任务目录与数据摘要未变化；
- 扩展升级和会话恢复可执行；
- 旧 `chaoxing_solve` 历史可读但旧 tool schema 不可调用；未完成 solver run 不自动恢复写入，重新运行前必须通过 `visual_observe` capability 重新识别
  tab/frame/attempt/page fingerprint；
- 无明文凭证或源路径泄漏到日志；
- 源 Profile 摘要未变化。

### 6.4 原子激活

所有必需校验通过后：

1. 写入 ready_to_activate；
2. fsync 关键 manifest/journal；
3. 用原子重命名或等价事务把 staging 注册为正式任务；
4. 更新任务注册表；
5. 启动导入任务进行首次运行检查；
6. 写入 activated；
7. 向用户报告成功、跳过项和需重新登录项。

激活前崩溃时，新版本忽略未完成 staging；激活后注册表与任务目录必须能通过 journal 自愈到单一状态。

## 7. Journal 状态机

| 状态              | 含义                 | 下次启动动作                          |
| ----------------- | -------------------- | ------------------------------------- |
| planned           | 已确认，未写入       | 可继续或取消                          |
| snapshot_created  | 源快照完成           | 校验快照后继续                        |
| migrating         | 正在逐类迁移         | 从最后一个幂等 checkpoint 继续        |
| validating        | 数据已写入           | 重新执行全部校验                      |
| ready_to_activate | 校验通过             | 完成原子激活                          |
| activated         | 已成为正式任务       | 执行首次启动/健康检查                 |
| completed         | 用户可用且报告已保存 | 不再自动运行                          |
| failed            | 已失败               | 保留脱敏报告，清理 staging 或允许重试 |
| rolled_back       | 激活后已撤回         | 恢复旧运行时入口，隔离失败任务        |

journal 不包含 Cookie、密码、令牌或页面正文。

## 8. 失败与回滚

### 8.1 激活前失败

- 不修改任务注册表；
- 清理或隔离 staging；
- 保留脱敏错误报告；
- 源 Profile 不变；
- 用户可以调整范围后重试。

### 8.2 激活后失败

- 停止导入任务及其 Agent；
- 从任务注册表隐藏失败任务；
- 保留失败任务只读快照以供用户授权后的诊断；
- 恢复旧运行时启动入口和原始 Profile；
- 不从新任务反向覆盖旧 Profile；
- 若用户在新任务产生了新数据，提供单独导出路径，不进行隐式双向合并。

### 8.3 版本回滚

新旧运行时在 G5 稳定窗口内并存。回滚包必须与发布清单绑定，并已验证：

- 旧运行时仍可读取原始数据；
- 新浏览器创建的数据不会使旧 Profile schema 发生变化；
- 更新服务可以暂停问题版本；
- 问学服务端协议在回滚兼容窗口内支持旧客户端；
- 失败版本的任务数据不会被另一任务错误加载。

## 9. 用户确认与透明度

迁移 UI 最终必须清楚说明：

- 选择的是哪一个旧 Profile；
- 会创建哪一个导入任务；
- 哪些数据会迁移、跳过或要求重新登录；
- 其他任务不会共享登录态；
- 源数据何时仍会保留；
- 如何取消、重试、删除导入任务或回到旧版。

视觉表达遵循 [统一 UIUX](../../../context/UIUX.md)；上述信息与确认步骤仍是功能性要求，不得省略。

## 10. 验收标准

迁移功能通过 G4，至少满足：

- 所有版本化 fixtures 均有确定结果；
- 重复运行不产生重复或数据扩散；
- 任意 checkpoint 崩溃后可继续、清理或回滚；
- 未选择 Profile 与其他任务的数据摘要不变；
- 导入登录态只存在于一个导入任务；
- 无明文敏感数据进入日志、临时文件或崩溃转储；
- OSCrypt 不兼容时安全降级为重新登录；
- 旧运行时在稳定窗口内可启动并读取原始数据；
- 跨账号来源的展示、重归属和迁移数量为 0；无归属来源未经过独立确认时迁移数量为 0；
- 用户新增数据有明确导出路径；
- 测试证据符合 [测试策略](TESTING.md) 的记录格式。

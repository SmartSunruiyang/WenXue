# 内置模型 tokens 成本估算

- 日期：2026-09-22
- 依据：用户提供的 Qwen3.7 Plus / Max 价格截图，并确认按原价计算。
- 归属：当前运行时 `ARCHITECTURE.md` 的 CloudBaseLlmGateway、UsageCloudClient、ConsoleUI。
- 工作树：独立 `codex/token-cost-pricing`，原工作区的账号/界面未提交改动保留。

## 规则

人民币 / 百万 tokens；实时调用，不应用限时折扣或 Batch File / Batch Chat 价格。

| 模型 / 输入档位              | 普通输入 | 隐式缓存命中 | 显式缓存创建 | 显式缓存命中 | 输出 |
| ---------------------------- | -------: | -----------: | -----------: | -----------: | ---: |
| qwen3.7-plus，输入 ≤ 256,000 |        2 |          0.4 |          2.5 |          0.2 |    8 |
| qwen3.7-plus，输入 > 256,000 |        6 |          1.2 |          7.5 |          0.6 |   24 |
| qwen3.7-max                  |       12 |          2.4 |           15 |          1.2 |   36 |

Plus 长输入价格补充自[官方模型文档](https://help.aliyun.com/zh/model-studio/qwen3-7-plus)。
[阶梯规则](https://help.aliyun.com/zh/model-studio/model-pricing)：K = 1,000，单次请求全部输入（含缓存）决定档位，输入/输出全部采用该档价格。
[缓存协议](https://help.aliyun.com/zh/model-studio/context-cache)：命中与创建 tokens 是总输入的子集；显式/隐式缓存互斥。

成本 =（普通输入 × 输入单价 + 命中 tokens × 对应缓存单价 + 创建 tokens × 创建单价 + 输出 × 输出单价）/ 1,000,000。
普通输入 = 总输入 − 命中 tokens − 创建 tokens。输入档位按总输入判断。

## 实施

1. 在现有网关模块内解析缓存计数，依据请求的显式缓存标记区分命中价格；仅保存计数、缓存模式、价格版本及金额，不保存请求正文。
2. 新记录保存按本次规则算出的费用；历史记录没有费用时按已有 tokens 补算，缺失缓存明细按普通输入估算。未提供价格的模型维持现有未估价行为。
3. 单次费用保留 0.0000001 元精度，累计后再保留界面所需的四位小数，避免小额请求被逐次舍入。
4. 云端 summary 与离线 summary 缓存沿用现有契约；本地 BYO-Key 原始日志不套用内置供应商价格。
5. 在现有 tokens 页补充可查看的原价、档位与历史数据估算说明，同步当前架构文档并写执行日志。

## 验证

- Plus / Max 标准调用、隐式命中、显式创建/命中、256,000 边界与完整输入判档。
- JSON / SSE 实际入口保存缓存数据和费用，云端读取后保留，历史记录补算。
- 大量小额调用累计、按日期/画像/模型汇总与总额一致；敏感信息不进入用量。
- 网关测试、类型检查，以及涉及的桌面检查和格式检查。
- 本任务不部署云端、不调用真实付费模型；上线需发布网关代码。

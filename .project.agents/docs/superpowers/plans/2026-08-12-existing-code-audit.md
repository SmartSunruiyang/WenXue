# 现有代码审查与优化计划

- **日期**：2026-08-12
- **范围**：当前 Electron + Chrome for Testing 运行时的全部已登记自有模块，以及受 I5 约束的
  `@page-agent/*` vendor 包
- **目标**：修复可复现或可由契约直接证明的缺陷，并实施高置信、行为保持型优化

## 审查边界

- 覆盖 `apps/desktop`、`apps/extension`、`apps/llm-gateway`、`apps/admin-api`、`apps/admin`、
  `apps/website` 与 `packages/client-operations`。
- `packages/{core,llms,page-controller,ui}` 视为上游快照；仅在缺陷影响问学运行时、回归测试明确且
  `UPSTREAM.md` 可同步登记时修改。
- 忽略 `out/`、`dist/`、`.output/`、`.browsers/` 等生成物，不把格式偏好或推测性风险当作修复任务。
- 不改变产品范围、模块边界或依赖方向；如证据表明必须改变，先暂停并与用户对齐。

## 执行步骤

1. 建立干净基线，读取当前运行时架构、规范、供应链与测试边界。
2. 运行快速静态门禁和现有测试，记录可稳定复现的失败。
3. 并行检查行为回归、安全隐私、性能可靠性和跨模块契约/覆盖。
4. 主会话合并并过滤发现；只保留有具体调用路径、失败场景或契约依据的问题。
5. 按风险由高到低修复，并为每个行为缺陷补最小回归测试。
6. 对最终差异执行复用、质量、效率和规范复核，只应用行为保持型简化。
7. 运行受影响模块测试、typecheck、lint 或构建中的最小充分集合，并写执行日志。

## 完成门槛

- 所有已修改行为都有可执行回归证据；关键测试、类型检查和构建无新增失败。
- 不引入新的敏感信息持久化、桌面到插件控制边或未登记 IPC/模块依赖。
- 最终报告列出已修复问题、已发现但未改问题、自动验证结果和模拟用户全链路测试步骤。

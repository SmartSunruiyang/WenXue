## 1. 背景与目标

现状启动器（`apps/desktop` 渲染层 `App.tsx` + `index.css`）是一张居中卡片：点一个「启动浏览器」主按钮，跑单一 `BrowserStatus` 状态机，开**一个**浏览器。这与产品要的"多开 + 永久日志 + 像 App 的工作台"不符。

本次把启动器从"单卡片启动器"重构为"**App 化工作台**"：

1. 无系统标题栏、白色单一主题、像桌面应用一样的默认窗口尺寸。
2. 常驻**窄图标侧边栏**作为全局导航。
3. 主区为**浏览器多开管理页**：可添加、重命名、多选并同时打开多个**持久画像**浏览器（多账号并行）。
4. **日志页**取代扩展内的日志功能：实时查看浏览器内问学插件的操作日志，永久保存，可手动删除 / 导出。
5. **Tokens 页**展示本机模型调用消耗趋势、模型分布与画像归因。
6. **设置页**集中管理"启动器启动浏览器的默认设置"等项。

### 1.1 范围

- **在范围**：启动器（桌面域 `apps/desktop`）的窗口外壳、导航、浏览器多开、日志页、设置页、本地资料菜单；以及为日志页所需的、**单向 插件→启动器** 的日志采集通道（§5.4 开放决策）。
- **不在范围**：扩展内部 Agent / LLM / 对话 UI 的改动；扩展日志采集点本身（沿用既有埋点，仅改"日志最终落到哪、由谁展示"）；品牌主色定稿（沿用现有 token 占位）；安装包签名。

### 1.2 取代关系（提示，后续回写）

本设计取代既有启动器行为：单状态卡 → 多开列表；固定小窗 → App 窗口；跟随系统深色 → 白色单一主题；扩展内日志 → 启动器日志页。`PRD.md` 的启动器小窗描述与 `UIUX.md` §3/§5/§6/§7 在本设计落地后需同步更新（本次不展开改这两份上游文档）。

## 2. 设计原则

1. **像一个 App，不像一个弹窗**：默认窗口大、可缩放、有持久导航；不是"点一下就消失的启动器"。
2. **白色单一主题**：只做浅色，**不做深色模式、不做明暗适配、不跟随系统**。删除现有 `index.css` 的 `@media (prefers-color-scheme: dark)` 整段，`color-scheme: light` 固定。
3. **克制的工具感**：沿用问学"克制、学术、工具"气质与既有配色 token；能量色只服务**状态与点缀**，不铺底、不喧宾夺主。
4. **过程可见**：浏览器运行态、启动中、异常，都有明确的状态点 + 文案；日志实时可见。
5. **用户可控**：浏览器可单开 / 多开 / 聚焦 / 停止；日志可清空 / 导出；启动默认值可配置。

## 3. 窗口与外壳（App Shell）

### FR-W1 无边框 + 跨平台窗口控件

- 隐藏系统标题栏，但**两端都要可用**：
  - **macOS**：`titleBarStyle: 'hiddenInset'` —— 隐藏标题栏，保留悬浮的系统红绿灯（关闭/最小化/缩放）于**左上角**。
  - **Windows**：`titleBarStyle: 'hidden'` + `titleBarOverlay: { color, symbolColor, height }`（Window Controls Overlay）—— 系统在**右上角**画出原生最小化/最大化/关闭三键，无需自绘。
  - Linux（非目标，但不阻断）：退化为自绘最小化/关闭或保留系统边框，按 Electron 默认。
- **可拖拽区**：侧边栏整体 + 主区顶部留白区设为 `-webkit-app-region: drag`；其中所有按钮 / 输入 / 列表项设 `no-drag`。
- **系统控件安全区（两端都要让位，且与右对齐操作不冲突）**：
  - **左上（mac 红绿灯）**：侧栏顶部头像下移到安全区之下。
  - **右上（win 三键）**：**任何页面顶部工具条上的右对齐主操作**（如「添加浏览器」「清空」「导出」）**必须为右上系统三键浮层预留右内边距（≈ 浮层宽度，约 138px），或整体起始于其左侧**，不得压在系统控件之下。
  - 同一套布局通过"两侧顶部各留安全区"兼容两端：mac 让左上、win 让右上。

### FR-W2 窗口尺寸

- 默认尺寸约 **1120×720**；最小约 **920×600**；可自由缩放，启动时**不**最大化。
- 记忆上次窗口尺寸与位置（写入设置存储），下次启动恢复。

### FR-W3 白色单一主题

- 全局浅色；移除深色媒体查询与 `useDarkMode` 相关逻辑；字标资产固定用浅色版。

### FR-W4 持久窄侧边栏

- 左侧**常驻图标栏**（宽约 64–72px），任何页面都不隐藏。自上而下：
  1. **头像**（顶部）—— 本地资料入口（§7）。
  2. **Chrome 图标** —— 进入「浏览器」页（默认页）。
  3. **日志图标** —— 进入「日志」页。
  4. **Tokens 图标** —— 进入「Tokens」统计页。
  5. 弹性空白。
  6. **设置图标**（底部）—— 进入「设置」页。
- 当前页对应的图标为**激活态**（高亮 + 可用左侧细条/底色表达）；hover 出现 Tooltip 文案；全部键盘可达、焦点态可见。
- 侧栏顶部为 mac 红绿灯让出安全区（头像下移到安全区之下）。

### FR-W5 主区路由

- 主区是**单视图路由**，由侧栏切换：浏览器页（默认） / 日志页 / Tokens 页 / 设置页。切换为瞬时或轻量淡入，无重型动效。

## 4. 浏览器页（多开核心 · 默认页）

### 4.1 数据模型 — Browser（= 持久画像）

每个"浏览器"是一个**持久画像**：独立 `user-data-dir`，登录态 / Cookie 各自隔离；多选并行打开即"多账号同时在线"。基于现有 `ProfileStore`（已支持多画像目录）扩展一层元数据。

```ts
interface BrowserProfile {
	id: string // 稳定 ID，匹配 ProfileStore 目录名 /^[a-zA-Z0-9_-]+$/
	displayName: string // 用户可改的展示名（可重复，仅 id 唯一）
	type: 'persistent' // 本期固定持久；'incognito' 预留（设置默认值可切，见 §6）
	colorKey: string // 头像色块用的品牌强调色键（从能量色板派生）
	createdAt: number
	lastUsedAt: number | null
	userDataDir: string // 由 ProfileStore 派生
}
```

- 元数据存于启动器侧 JSON（app `userData`，见 §8），与 `ProfileStore` 目录一一对应；删除画像时同时清理目录与元数据。

### 4.2 功能需求

- **FR-B1 列表展示**：以列表（每行一项）展示全部已保存浏览器。行内含：左侧**多选复选框**、首字母色块/图标、**展示名**、**状态点**（idle 灰 / launching 珊瑚 / running 绿 / error 红，配文字标签）、上次使用时间（相对时间，等宽）。
- **FR-B2 添加浏览器**：显著的「添加浏览器」入口 → 创建新持久画像（生成 id + 默认名如「浏览器 N」+ 分配一个色块），创建后进入就地重命名态。
- **FR-B3 重命名**：双击行名或点笔形图标进入**就地编辑**；回车保存、Esc 取消；空名回退为默认名。
- **FR-B4 多选 + 批量打开**：可勾选任意多项；选中后底部浮出操作条「**打开选中 (N)**」+「取消选择」。点击同时启动 N 个浏览器，每个用各自画像 + 注入问学插件。
  - 受设置约束：**同时打开上限** 与 **错峰间隔**（§6 启动默认值）——超过上限时提示并分批；错峰间隔用于避免瞬时资源尖峰。
- **FR-B5 单行操作**（hover 显示 / 右键菜单）：打开（单个）、聚焦（running 时置顶窗口）、停止、重命名、复制为新画像、删除（二次确认，说明会清除该画像登录态/缓存）、打开画像文件夹。
- **FR-B6 运行态反馈**：行进入 launching → running → error 时实时更新状态点与可用操作（running 行的主操作变「聚焦 / 停止」）。可选地为 running 行加一道**轻**的品牌运行态描边（不喧宾夺主，§10）。
- **FR-B7 空状态**：无任何浏览器时，居中品牌空态（问字 logo 克制呼吸）+「添加第一个浏览器」主按钮。
- **FR-B8 排序与搜索**（≥ 一定数量时启用）：按最近使用 / 名称排序；顶部可选搜索框按名称过滤。数量少时可不显示，避免冗余。

### 4.3 与现有运行时的关系

- 现状 `BrowserSupervisor` 是单浏览器状态机；多开需要把"单实例看护"提升为"**按画像并行看护多实例**"。本文仅出功能需求；运行时改造（多实例管理、进程表、各自状态广播）在实现计划中拆解，**不在本设计内定型代码**。

## 5. 日志页（取代扩展内日志）

目标：把"浏览器内问学插件的操作日志"统一收到**启动器**展示与持久化，替代扩展 Sidepanel 内的 `LogViewer`。

> **替代闭环**：扩展内 Sidepanel 的 `LogViewer` 在本启动器日志页上线后**下线**（避免两个查看器并存）；扩展侧的**采集埋点保留**，仅改"日志最终落到启动器、由启动器展示"。

### 5.1 复用既有日志模型

沿用扩展现有日志结构（`apps/extension/src/lib/logTypes.ts`），**新增一个"浏览器/画像"维度**用于多开归类：

```ts
interface LauncherLogEntry {
	id: number
	ts: number
	level: 'debug' | 'info' | 'warn' | 'error'
	source: 'agent' | 'llm' | 'tabs' | 'page' | 'chaoxing' | 'config' | 'system'
	context: 'background' | 'sidepanel' | 'newtab' | 'hub' | 'content'
	browserId: string // 新增：来自哪个画像/浏览器（多开归类）
	message: string
	data?: unknown // llm 来源载荷须已脱敏（见 §5.4 / I2）
}
```

### 5.2 功能需求

- **FR-L1 实时串流**：以**实时 tail** 展示日志；提供「跟随最新 / 暂停」开关；虚拟滚动承载大量条目；等宽字体；时间戳、级别色标、来源标签清晰。
- **FR-L2 永久保存**：日志写入启动器侧磁盘存储（app `userData`，见 §8），**重启不丢**；不依赖浏览器 IndexedDB。
- **FR-L3 筛选**：按 **级别**（多选）、**来源**（多选）、**浏览器/画像**（多选）、**全文搜索**、**时间范围** 过滤；筛选即时生效。
- **FR-L4 手动删除**：支持「**清空全部**」与「**按当前筛选删除**」，均二次确认。
- **FR-L5 导出**：支持导出为 **JSON / NDJSON / 纯文本**；可导出全部或当前筛选结果；落地为用户选择的文件。
- **FR-L6 保留策略**：复用扩展 `purge()` 的语义——按**保留时长（retentionDays）**与**最大条数（maxEntries）**自动裁剪（先删过期、再按最旧裁至上限）；阈值在设置页可调（§6）。
- **FR-L7 单条详情**：点击条目展开 `data` 全文（JSON 折叠/展开）；长内容在框内滚动，不撑宽页面。
- **FR-L8 来源/级别图例**：顶部提供级别与来源的色彩/标签图例，状态不只靠颜色（无障碍）。

### 5.3 行为细节

- 多开时，不同浏览器的日志交织进同一时间线，用 `browserId` 色点/标签区分，并可在筛选里只看某个浏览器。
- 浏览器关闭后其历史日志**保留**（永久），仅停止新增。

### 5.4 ⚠️ 开放架构决策（需产品/架构拍板）— 日志采集通道

**冲突陈述**：日志页要"**实时**看到浏览器内插件日志"，这是**跨域运行时通信**，直接抵触铁律 **I3（Demo 阶段两域零运行时通信）**；并且 `llm` 来源日志载荷必须保持 **I2** 的脱敏（`logRedaction.ts`），**API Key 绝不能进入桌面进程**。本决策不在 UI 文档内解决，记为开放项。

**已选方案：Chrome Native Messaging（单向 插件 → 启动器）**（产品已选；前提：**mac 与 Windows 都适配**）

- **形态**：扩展声明 `nativeMessaging` 权限，经 `chrome.runtime.connectNative(<host>)` 把日志条目**单向推送**给启动器侧的原生消息宿主；宿主把条目写入启动器持久日志存储；日志页从该存储读取与展示。
- **单向性保证 I3 之魂**：通道只承载"插件 → 启动器"的遥测**出口**，启动器**不经此通道回送任何控制指令**给 Agent —— 两域无运行时**控制**耦合，只有单向日志外发。需在 `SELF_CONSTRAINTS.md` 为 I3 增列**明确豁免条款**（"允许单向日志遥测出口；禁止反向控制"）。
- **跨平台适配（关键前提）**：Native Messaging 在 Chrome 的 mac / Windows / Linux 均支持，差异仅在**宿主清单注册位置**，由启动器在**首次运行时自动写入**：
  - macOS：写入 Chrome for Testing 变体的**固定用户级目录**（形如 `…/Google/Chrome for Testing/NativeMessagingHosts/<host>.json`）。**注意**：Chrome 从每个变体的**固定位置**解析清单，未必等同我们启动时指定的 `--user-data-dir`；**确切路径以实现期对照 Chrome 官方 Native Messaging 文档为准**。
  - Windows：写入注册表 `HKCU\Software\Google\Chrome\NativeMessagingHosts\<host>`，值指向清单 JSON 路径。
  - 清单中 `allowed_origins` 锁定本扩展 ID；`path` 指向启动器随附的宿主可执行（可为 Electron 应用自身的子命令或随包的小型 helper）。
- **I2 脱敏约束**：扩展在**发送前**对 `llm` 载荷执行 `logRedaction.ts` 脱敏；宿主侧**不信任、再断言一次**（二次清洗），确保 API Key / 敏感头永不落入桌面存储。
- **降级**：宿主未注册 / 连接失败时，日志页显示"未连接"引导，并提供"修复连接（重写宿主清单）"按钮；扩展侧日志仍可本地暂存，连接恢复后补传（实现期细化）。

**备选（记录，未采用）**：① 本地回环 HTTP 槽（`127.0.0.1:<port>`，需开端口）；② 共享文件 NDJSON tail（扩展用 downloads 写、启动器尾随，较脆、无补传）。

> **待办（拍板项）**：在 `SELF_CONSTRAINTS.md` 增列 I3 的"单向日志遥测出口"豁免；确认宿主可执行形态（Electron 子命令 vs 独立 helper）；确认宿主清单的 OS 注册细节与 CfT `--user-data-dir` 的关系。

## 6. 设置页（启动器设置）

> 方向："控制启动器**启动浏览器的默认设置**"，并涵盖启动器自身行为、日志策略、内核信息、关于。分 5 组，左侧分类 + 右侧内容；改动即时保存，无保存按钮。带 ★ 为建议本期落地，其余可后续。

### 组 1 · 启动默认值（启动浏览器时套用）

- ★ **默认窗口尺寸 / 位置**：新开浏览器窗口的默认宽高与落点。
- ★ **起始页 URL**：浏览器打开时的首个页面（默认问学新标签引导页 / 自定义 URL）。
- ★ **同时打开上限**：批量打开的并发上限（超过则分批）。
- ★ **错峰间隔**：批量打开时每个实例之间的启动间隔（毫秒），避免资源尖峰。
- **新建画像默认类型**：持久 / 无痕（无痕为预留，关系到 §4.1 `type`）。
- **代理**：无 / 跟随系统 / 自定义（host:port）。
- **界面语言**：传给浏览器的 `--lang`。
- **默认缩放 / 字号**。

### 组 2 · 启动器行为

- ★ **关闭按钮行为**：最小化到托盘 / 直接退出。
- ★ **退出时浏览器仍在运行的处理**：每次询问 / 仅退出启动器 / 一并关闭浏览器（复用既有 `requestShutdown` 契约与"不连坐"决策）。
- **开机自启**。
- **默认下载目录**。

### 组 3 · 日志

- ★ **保留时长（retentionDays）** 与 ★ **最大条数（maxEntries）**：驱动 §5.6 的自动裁剪。
- ★ **最低捕获级别**：debug / info / warn / error。
- **是否捕获 LLM 请求/响应**：开启时附"载荷已脱敏（I2）"说明。
- **默认导出格式**：JSON / NDJSON / 纯文本。

### 组 4 · 浏览器内核

- **CfT 版本信息**（只读）+ **重新拉取 / 修复**。
- **打开画像根目录**（`profilesRoot`）。

### 组 5 · 关于

- **三元版本号**：App / 浏览器内核 / 插件（等宽，长版本截断）。
- **打开日志目录**、外部链接（仓库 / 文档）。

## 7. 头像 · 本地资料 + 菜单

- 侧栏顶部头像代表**本地用户**（**不接入云账号**；后续可平滑升级为问学账号）。
- 点击头像弹出轻量 Popover 菜单：**资料**（展示名、更换头像/色块）、**设置**（跳设置页）、**关于**、**退出**。
- 资料数据存于设置存储（§8）；默认头像为品牌占位（首字母色块）。

| 画像目录（user-data-dir）  | `ProfileStore.profilesRoot()` 下各 id 目录                                       | 沿用现有；多开各自隔离                           |

| Native Messaging 宿主清单  | mac：用户级 `NativeMessagingHosts/`；win：注册表 `HKCU\...\NativeMessagingHosts` | 首次运行自动写入（§5.4）                         |

## 9. 非功能需求

- **NFR-1 性能**：冷启 → 窗口可交互 ≤ 2s；日志页万级条目虚拟滚动不卡顿（60fps 目标）；实时日志低延迟（亚秒级到达）。
- **NFR-2 无障碍**：全键盘可达（侧栏导航、列表、复选框、对话框）；焦点态可见；状态不只靠颜色（配文字标签）；尊重"减少动态效果"。
- **NFR-3 安全（I2）**：API Key / 敏感头永不进入桌面进程；日志载荷跨通道前已脱敏，宿主侧再断言一次。
- **NFR-4 一致性**：复用既有配色 token 与字体栈；图标统一 Lucide。
- **NFR-5 单一主题**：全程白色，无任何深色代码路径。

## 10. 配色与品牌（复用插件既有 token）

只取**浅色** token（源自 `apps/desktop/src/renderer/src/index.css`，**删除其深色段**），作为本设计调色板：

- 底/前景：`--wx-background: oklch(0.985 0 0)`（近白）、`--wx-background-deep: oklch(0.92 0 0)`、`--wx-foreground: oklch(0.12 0 0)`（近黑）、`--wx-muted: oklch(0.44 0 0)`、`--wx-muted-soft: oklch(0.58 0 0)`。

- 能量强调色（**仅状态与点缀**）：电蓝 `oklch(0.72 0.18 245)`、激光紫 `oklch(0.72 0.22 305)`、量子青 `oklch(0.78 0.18 185)`、信号绿 `oklch(0.74 0.17 150)`、珊瑚 `oklch(0.76 0.18 35)`、错误红 `oklch(0.64 0.24 25)`。

## 12. 验收要点（高层）

- 打开 App：无系统标题栏（mac 留红绿灯 / win 留右上三键），白色，窗口约 1120×720，左侧常驻图标栏。
- 浏览器页：能添加、就地重命名、多选并同时打开多个浏览器；各画像登录态互不影响；运行态实时反馈。
- 日志页：实时看到插件日志、重启不丢、可按级别/来源/浏览器/全文/时间筛选、可清空、可导出（JSON/NDJSON/文本）。
- 设置页：可改启动默认值（尺寸/起始页/并发上限/错峰）、关闭行为、退出处理、日志保留阈值，且即时保存。
- 头像菜单：可见本地资料 / 设置 / 关于 / 退出。
- 全程无深色路径；I2 脱敏成立；日志通道单向。

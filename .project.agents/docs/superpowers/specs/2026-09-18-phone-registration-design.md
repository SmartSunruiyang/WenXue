# 手机验证注册与已绑定号码登录

- 状态：按用户 2026-09-18 补充要求实施
- 上游：目标 PRD F10、当前 ARCHITECTURE ConsoleUI、UIUX 认证交互

## 验收规则

- 已绑定号码输入短信码后仅登录原 uid；密码登录保持可选。手机号不存在时，引导注册页，填写合法用户名、密码和该手机号；注册完成前必须验证绑定短信码，不能进入工作台。
- 直接从注册页进入也必须填写手机号并验证。手机号已归属其他账号时，弹窗要求放弃注册、转短信登录；不得改写旧账号凭据或创建重复手机号。注册期间失败/取消可重试，不能留下以手机号自动创建的空账号。
- 之前 OTP 自动创建但缺少用户名/密码的账号，以同 uid 补全注册资料并再次验证短信码；若云端状态不允许激活则明确报错，不修改冻结状态。
- 账号会话最后仍走主进程 → 网关 ACTIVE 身份验证，错误要指明是注册未完成、号码已占用或云端身份校验失败。

## 实现边界

- 已有号码 OTP `shouldCreateUser: false`；无账号在发送或核验阶段收到 `not_found` 时切换注册并预填手机号。
- 新注册通过 CloudBase SDK `signUp({phone, username, password})` 发码，`verifyOtp` 后校验手机号、用户名和新建结果才交接会话。SDK 的 `signUp` 对已存在号码可能直接登录：注册路径必须检测并拒绝该结果，退出其会话并提示转登录。
- 老版本残留的已占用但未完成账号，凭短信登录后的同 uid 会话进入补全页面；使用 SDK 的 `updateUser({username})` 和 `reauthenticate()` 短信码设置密码。所有关键结果核验 uid 不变。
- 不扩展 CloudBase 管理端或修改 `BLOCKED` 用户状态；后端既有注册接口仍供旧客户端使用。图形验证码、60 秒频控及超时互斥复用原实现。

## 界面设计

- 目的：把“先验证手机号再进入工作台”的注册责任展示在原账号入口，让用户清楚知道是否在注册或登录。
- 美学：既有轻量工具式表单；色彩沿用 #FFFFFF、#0A0A0A、#171717、#666666，状态沿用语义绿色/红色；字体沿用项目已批准的 system-ui、PingFang SC、Microsoft YaHei。
- 布局：原居中表单和分段控件，注册先填用户名/密码，再在同一卡片填写并验证手机号；手机号已用时原生模态提供“放弃注册并登录”。已有设计规范优先于通用 UI 指南对字体和居中布局的限制。
- 标签、错误、步骤状态和键盘操作可访问；仅在内存保留一次性验证码挑战及注册时密码。

## 验证

单测覆盖登录绝不建号、新号码引导、首次注册账号结果及手机号核验、已存在号码竞态拒绝、残留账号补全、UID/会话安全边界；桌面类型检查、lint、构建和隔离浏览器预览验证。真实短信/真实云端账户仍需单独验收。

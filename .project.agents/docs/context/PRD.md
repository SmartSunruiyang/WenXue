# 问学 WenXue — 产品需求文档（PRD）

> ask for everything
>
> 状态：当前产品需求入口，2026-09-25 恢复。用户已明确废弃 Chromium AI 浏览器重构，继续维护 Electron + Chrome for Testing（CfT）方案。
> 本文恢复原 Electron PRD 的功能编号和当前产品边界，并按现有架构及已批准修订更新账号、视觉能力与引导要求；不将旧版用户名注册等过时行为重新引入产品。
> §6 的正式发布、公告与更新需求已由用户确认，当前进入 P0；实现与生产验收按 [实施计划](../superpowers/plans/2026-09-25-desktop-release-notifications-updates.md) 推进。需求已确认不代表功能已经可用。

## 1. 一句话定位

问学是供用户在场使用的桌面网页操作助手：Electron 工作台管理内置 CfT 浏览器与独立画像，问学 MV3 插件提供侧边栏对话、多标签页 Agent 和视觉辅助，帮助用户完成资料检索、表单填写等网页任务。

## 2. 当前产品路线

- 保留 Electron 启动器、内置 CfT 和问学插件的现有组合；CfT 与插件随桌面安装包交付。
- 本轮正式分发与实机验收目标仅为 macOS Apple Silicon（arm64）和 Windows x64，使用未签名 DMG/NSIS；Intel Mac 暂不适配，也不列入本轮发布和验收目标。
- CloudBase 承载用户认证、内置模型网关、用量与管理接口，COS 承载发布产物；沿用现有服务。
- Chromium 源码浏览器重构及其 G0–G6 门禁已废弃，[历史资料](../refactor/ai-browser/README.md)仅供追溯，不约束当前开发，不要求现有功能继续同步到该域。

## 3. 用户与使用场景

| 用户             | 主要诉求                                                       |
| ---------------- | -------------------------------------------------------------- |
| 桌面用户         | 登录问学、管理多个浏览器画像，在网页中发起任务并随时停止或接管 |
| 高级用户         | 配置自定义模型、查看本地执行历史与日志、理解用量和失败原因     |
| 管理员           | 管理用户访问、查看脱敏用量、发送公告并控制版本发布             |
| 新安装和已有用户 | 从官网获得正确安装包，保留原有资料完成后续升级                 |

## 4. 产品形态与职责

| 表面                 | 职责                                                         |
| -------------------- | ------------------------------------------------------------ |
| Electron 工作台      | 认证入口、画像启动和状态、日志、tokens、设置、公告与更新展示 |
| 内置 CfT             | 标准浏览器能力和各画像独立的站点数据、登录状态与插件存储     |
| 问学 MV3 插件        | 对话、Agent 执行、跨标签页操作、视觉辅助、模型配置和本地历史 |
| CloudBase 网关与后台 | 鉴权、内置模型透传、计量、管理员授权、公告和版本控制         |
| 官网与 COS           | 产品与使用文档入口、有效正式版本下载、不可变安装包分发       |

模块划分、进程通信和存储边界由 [ARCHITECTURE](ARCHITECTURE.md) 定义；本文不新设运行时模块。

## 5. 当前功能基线

以下 F 编号沿用原 Electron 产品文档，便于旧计划和验收记录追溯。它们描述应保留的功能行为；实现进度和缺少的实机证据分别见 [ROADMAP](ROADMAP.md) 和执行日志。

### F1 浏览器画像工作台

- 用户可添加、重命名、打开、聚焦和停止多个持久画像，查看真实运行状态；同一画像同时至多运行一个实例，不同画像可并行。
- 画像按当前账号隔离；切换账号不得展示或操作其他账号资料。退出登录须先安全停止相关画像，磁盘资料保留。
- 普通关闭工作台保留现有退出选择，不因关闭窗口无条件终止浏览器；更新安装采用 §6 的额外安全条件。
- 验收：重复启动不产生同画像双实例，进程退出后状态回落，账号切换不泄露画像，重启后资料仍在。

### F2 内置浏览器与插件

- 安装包内置锁定版本的 CfT 与问学插件，用户无需自行安装插件或从浏览器商店获取。
- 浏览器打开后可从工具栏进入问学侧边栏，插件配置、历史与稳定的存储身份在重启及升级后保留。
- 资源缺失、启动或插件加载失败需有可理解的错误和排查路径。
- 验收：真实安装包启动 CfT 并验证插件注入；开发模式成功不能代替此项。

### F3 侧边栏对话与网页 Agent

- 支持自然语言任务、执行过程反馈、Markdown 结果、多标签页操作和本地历史回看。
- 完成或失败后可在同一会话续接；新建对话建立显式上下文边界；上下文压缩不删除本地原始历史。
- 用户可停止任务；登录、验证码、权限确认和不可操作区域转人工接管，不自动绕过。
- 保留当前 JavaScript/frame 执行与视觉观察边界，页面权限限制和不确定结果必须如实呈现。
- 验收：已有 research 和标准表单示例的完整交互可复现；任务中止、人工接管和续接仍可用。

### F4 模型配置

- 内置文本与视觉模型通过现有 CloudBase 网关和用户 session 使用；具体模型及配置由 TECH-INFRA 管理。
- 自定义 OpenAI-compatible 模型支持 URL、模型名和用户 API Key，凭据留在本机；自定义请求维持直接访问用户配置的端点。
- 会话缺失或过期应提示重新登录；不得退回内置厂商 Key 的客户端直连路径。
- 验收：内置模型和自定义模型分别遵守各自鉴权路径，错误可理解且不会泄露凭据。

### F5 新标签页与插件入口

保留新标签页、快捷入口、插件设置与现有独立页面体验；这些入口不代替启动器的账号和画像所有权校验。视觉遵循 [UIUX](UIUX.md)。

### F6 视觉观察与统一答题能力

- `visual_observe` 是现有视觉能力入口；普通观察保持只读，不因发现题目便自动作答或填写。
- `question_solver` 按明确请求区分 inspect、answer、fill，只有获准的 fill 可以改写页面；不自动提交，不绕过登录、验证码或其他平台保护。
- 平台适配、页面写入、结果验证和成熟度按当前架构与已有设计管理，fixture 验证不得宣称是真实平台验证；保留用户核对和接管。

### F7 日志与排障

保留日志查看、筛选、详情、导出、清理与保留期限。插件本地历史和已脱敏记录、桌面日志、云端计量的边界遵守 ARCHITECTURE I2/I3；凭据不得进入日志，云端计量不保存对话正文。桌面不得借日志通道控制插件 Agent。

### F8 Tokens 与成本展示

展示当前账号的云端计量、模型与画像归因、最近明细和参考成本；云端不可用时仅显示同账号的允许缓存或本地记录。成本估算可解释，不等同于已实施的订阅扣费。

### F9 用户认证与本地账号隔离

- 当前登录采用 CloudBase 邮箱密码或邮箱验证码；新邮箱验证后提交完整资料才创建账号，并提供密码重置。
- 登录入口说明「继续即表示你已阅读并同意问学的隐私协议和用户须知」，两项分别链接到正式官网 `https://askwenxue.com/#privacy/privacy-policy` 与 `https://askwenxue.com/#privacy/terms-of-use`，通过系统浏览器打开。
- 内置网关以 CloudBase Auth 的 ACTIVE/BLOCKED 状态决定访问，历史 `user_accounts` 记录不承担认证授权。
- 未登录不进入账号工作台和画像操作；公开版本检查与正式安装包下载不应要求用户先登录。
- 启动器向插件交接现有会话，保持一次性 handoff、刷新和敏感信息边界；不新增机器 token 登录或用户名注册路径。

### F10 后台管理

管理后台验证 CloudBase session 与 active `admin_users` 角色，支持现有邮箱/内部账号登录；普通注册不授予管理权限。用户状态、用量、公告和发布分别校验权限，viewer 只读。关键管理写操作保留审计，不能将未经回读确认的操作显示为已生效。

### F11 首次使用引导

仅在六段正式实机素材齐备时，为没有画像且尚未完成引导的账号展示现有教程；可以跳过，按本机账号记录进度，并遵循重播、减少动态效果和素材缺失时的降级规则。公告、更新或退出确认不与教程争抢交互；引导本身不创建画像或调用模型。

### F12 官网演示素材

2026-09-26 用户决定不再保留 `wenxue-work-demo.mov`：移除官网首页的网页任务录屏区块和文档中的对应视频引用。保留独立的工具栏教学视频及步骤；首页“看演示”入口指向保留的教学区块。不采用 Git LFS 保存被移除的视频。

| R9   | 旧版经一次手动安装进入过渡版                                         | 验证真实旧版 → 过渡版 → 后续版；保留应用标识、安装身份和数据目录                              |

补充边界：

- 2026-09-26 用户选择 GitHub 私有仓库免费套餐：GitHub 仅做无发布凭据的构建/测试，可信本机负责候选签名、不可变上传与注册，不依赖付费分支保护或发布 Environment。免费额度耗尽时停止使用，不采购套餐或额外额度。
- 暂不办理平台签名；自有 Ed25519 清单签名和 SHA-512/大小校验继续保留，不得称其为 Apple/Windows 平台签名。
- 本轮使用允许稍后更新的体验。既有 mandatory 策略的兼容在 P2 明确，不能扩大为强制重启、强杀 CfT 或离线自动安装。
- 关闭窗口、保留 CfT 的启动器退出和关机/注销不构成安全安装时机；普通应用使用不能被更新失败阻断。
- 服务端撤回不能召回已经启动的安装器或应用之外保存的安装包；已升级用户通过更高版本修复包恢复，不承诺自动降级。
- 公告只要求登录客户端接收，不要求完全退出应用后仍弹系统通知。
- 登录、网络恢复及重新回到客户端时立即补拉待确认公告；重复恢复事件不制造重复弹窗。
  确认失败保留重试入口，确认成功后迟到的同步请求不得重新弹出同一消息。

## 7. 非目标与能力边界

### 7.1 本轮不做

Chromium 源码浏览器重构、Linux/Windows ARM 新平台、macOS 自动安装、平台签名采购、订阅计费改造、替代后台或 LLM/Agent 功能扩张均不在本轮范围。平台签名与 Mac 自动安装可在未来独立立项。

### 7.2 行为与验收边界

页面权限、sandbox、浏览器特权页和平台防护可能限制网页自动化；视觉判断不等同于确定执行成功。安装器受系统权限、安全策略和文件占用影响，UI 必须如实说明，不能承诺所有未签名环境无提示安装。

### 7.3 产品红线

- 保持用户在场、可停止、可接管，不开发验证码绕过、反检测或浏览器指纹伪装能力。
- 最终提交等高影响页面操作保持现有明确授权边界；用户可核对生成内容。
- 保留 AI 生成内容提示和上游 MIT 版权；不因发布流程改造改变许可或凭据保护要求。

当前交付顺序为 P0 文档与基线 → P1 复现与配置核验 → P2 契约 → P3 公告 → P4 候选 CI → P5 客户端更新 → P6 后台与官网 → P7 实机演练和受控发布。

详细任务、依赖和状态只在 [实施计划](../superpowers/plans/2026-09-25-desktop-release-notifications-updates.md) 维护；[ROADMAP](ROADMAP.md)保留既有 M0–M5 工程记录并展示本轮阶段入口，历史勾选不表示当前生产端到端可用。

## 9. 验收与成功条件

- 现有 F1–F11 行为不得因更新改造回归，尤其是画像/账号隔离、会话与历史保留、真实 CfT 启动及插件注入。
- macOS arm64 和 Windows x64 两个目标均使用真实安装包验证；Intel Mac 暂不适配。构建、单元测试和开发预览不能替代安装/升级结果。
- 公告与发布流程按计划的 N/U/M/R 用例记录证据；秒级通知目标和故障补偿周期在 P1 固定环境后核验，不作为尚未测得的现状。
- 未有实机或生产证据的项目保持待验收；没有收到升级结果不等于安装失败，也不能推定成功。

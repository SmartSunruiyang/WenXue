# 问学 WenXue — UI/UX 设计指南

> 视觉与交互细节的权威（与 `PRD.md` 并列上游）。视觉/交互改动先改本文，再让派生实现 spec 对齐。
> 本项目有两个 UI 面：**桌面控制台**（Electron 渲染层）与**浏览器侧边栏**（插件 SidepanelApp）。两者共享同一品牌与 token 体系。

## 1. 设计原则（优先级递减）

1. **用户在场、用户可控**：Agent 是协作者不是接管者——任务随时可停止、可人工接管；绝不隐藏 Agent 正在做什么（呼应 PRD §7.3 合规定位）。
2. **过程可见**：每一步操作都有可解释的可视反馈（模拟光标、元素遮罩高亮、侧边栏活动流），用户始终能回答"它现在在干什么"。
3. **不遮挡工作现场**：智能面板以侧边栏形态存在，永不覆盖页面内容；启动器作为独立 App 工作台，不使用营销页或弹窗式布局。
4. **安静与克制**：桌面端常态零打扰，只在异常（浏览器崩溃）时系统通知；视觉可使用问学能量玻璃语言，但动效必须服务状态识别，不引入声音或无意义装饰。
5. **双端一致**：桌面控制台与侧边栏共用品牌、色板语义与文案语气。

## 2. 视觉身份

- 名称：中文「问学」，英文 "WenXue"；slogan "ask for everything"（小写，作副标题排印）。
- 品牌基调：克制、学术、工具感——像一件趁手的研究工具，不做拟人化吉祥物。
- 应用图标 / 插件图标 / 品牌主色：**待定**（PRD 开放问题 #1），定稿前用单色字标占位；资产规格见 §11。
- 无启动屏：主窗口直接呈现（冷启预算见 §10）。

## 3. 色板与字体

- 颜色一律走语义 token（shadcn / Tailwind CSS 变量体系）：`background` / `foreground` / `primary` / `muted` / `border` / `destructive` 等，**禁止散落 hex**；品牌主色定稿后只改 token 层，组件零改动。
- 插件侧可沿用上游深浅色；**桌面启动器固定白色单一主题**，不跟随系统深色模式。
- 字体：系统栈 `system-ui, PingFang SC, Microsoft YaHei`；版本号/日志用等宽 `ui-monospace`。
- 层级：标题 16–18px/600，正文 14px/400，辅助 12–13px/`muted-foreground`。中文正文不小于 13px。

## 4. 间距与栅格

- Tailwind 默认 4px 基数刻度；组件间距只用预设档（2/3/4/6/8 → 8–32px），不写任意值。
- 桌面主窗口内容区统一 24px 内边距；侧边栏沿上游布局栅格不动。

## 5. 动效与触觉

- 沿用插件上游动效体系（motion 过渡、打字流式动画、rough-notation 元素高亮），不新增与任务无关的动效。
- **运行态边框 = 问学流体玻璃（Liquid Glass）体系**，统一应用于网页遮罩边框与侧栏/Hub 运行态包边（替代上游 ai-motion WebGL 跑马灯）：
  - 主体为黑灰白半透明液态玻璃**由实到虚包边**：最外侧一段**实体玻璃带**（全不透明，侧栏 8px / 网页 10px）→ 经缓出曲线（中途 25% 停靠点：20px / 24px）羽化 → 至侧栏 40px / 网页 48px 处完全消散（双方向渐变 mask 取并集），**无硬内边**；效果只占边框区域，**不遮挡内容区**（`backdrop-filter` blur+saturate 折射页面内容，中性白→灰→黑渐变体）；
  - 柔和彩色光（低饱和蓝/紫/青/橙色段）**只沿边缘流动并随羽化消散**：双层 conic-gradient 反向异速旋转（约 9s / 14s），重度模糊呈果冻光感；
  - **最外缘流光玻璃环**：清晰可见的细环（侧栏 3px / 网页 4px），白玻璃底（65% 不透明度）+ 高饱和彩色脉冲段（蓝/紫/青/珊瑚，接近全不透明），随流转动（9s），不模糊、不参与果冻缩放（始终贴边）——它是"明显的边缘"主体，柔光层为其聚拢氛围；
  - 果冻呼吸：覆盖层以 ≤0.4% 振幅缓慢缩放脉动；外缘 1px 玻璃高光 + 柔和内里光泽（白色 sheen + 极淡暗部景深，均为大半径内阴影，不形成线）；
  - 空闲时动画暂停（`animation-play-state`），遵守 §8 减少动态效果（开启时流光静止为常亮玻璃罩）。
- 页面遮罩与模拟光标：淡入淡出 ≤ 200ms，缓动 `ease-out`；流体玻璃边框淡入淡出 ≤ 600ms。
- **桌面启动器**使用“小窗高能控制台”风格：首屏 logo / 主面板 / onboarding / 版本区分层进入（500–800ms），状态面板使用 Liquid Glass + Energy Edge 包边，运行态边缘流光最明显；主按钮 hover 使用横向光扫与轻微上浮。动效遵守 §8 减少动态效果，开启时停用循环动画与光扫位移，仅保留静态玻璃材质和清晰状态色。桌面端无音效、无触觉反馈。
- 2026-06-28 起，桌面启动器回到官网 / 插件 options 页一致的白底克制产品 UI：黑白品牌 logo、系统字体、细边框、8px 圆角、低色彩占比；保留必要状态色，避免大面积玻璃装饰和未绑定功能的装饰按钮。

## 6. 状态系统

**桌面控制台**（单一状态卡表达 BrowserStatus，与 ARCHITECTURE §1.2 状态机一一对应）：

- `idle` 未运行：主按钮「启动浏览器」可用。
- `launching` 启动中：按钮禁用 + 行内 spinner（≤10s 预算），显示「检查资源 / 启动浏览器 / 加载插件」非百分比启动序列。
- `running` 运行中：绿色状态点 + 「浏览器运行中」+ 按钮变为「聚焦窗口」。
- `error` 异常退出：destructive 色状态卡，给出"查看日志 / 重新启动"两个动作；同时发一条系统通知。

**侧边栏**：

- 用户 session 缺失或过期：聊天内联提示“登录已过期/无权限，请回到桌面端登录或重新启动浏览器”；内置默认模型经 CloudBase Gateway 使用用户 session。自定义模型区域仍提供 API Key 输入。
- 空闲：品牌空状态居中呈现——问字 logo（克制呼吸 + 轻微悬浮）+ 无底 slogan 字标图；下方不放 GitHub / 文档 / 主页入口按钮，不放独立装饰符号、光晕、阴影或圆形波纹，输入框聚焦。
- 输入区（底部）：与内容区之间不设分隔线；输入框大圆角（`rounded-2xl`，16px），输入正文 14px；输入框内下方操作行——左侧为模型快捷下拉（显示当前模型名，菜单含内置/自定义模型与「管理模型」入口，执行中禁用），右侧为状态点 + 发送/停止按钮；聚焦光晕为中性黑灰（不用彩色，呼应 §2 品牌基调）；占位文案以打字机轮播任务示例（遵守 §8 减少动态效果偏好）；输入框下方居中常驻 10px 灰字「内容由 AI 生成」（呼应 PRD §7.3）。
- 右上角：小加号新建对话按钮 + 历史按钮 + 三点更多菜单；点击历史按钮后，历史记录页从该按钮坐标以轻量裁切 / 缩放动效展开，减少动态效果开启时退化为瞬时切换。更多菜单使用轻量弹出动效，包含「设置」与「语言」。设置打开插件 options 设置页；语言提供界面语言与 Agent 回复语言快捷切换。
- 新建对话：点击小加号后，当前可见对话流先播放约 520ms 的收束动效，整体向右上角历史按钮缩小并淡出，历史按钮同步轻微响应；随后清空任务、步骤与活动态，并让品牌空态 logo 与 slogan 缓缓浮现。已写入 IndexedDB 的历史记录不受影响。运行中任务需先停止，运行中小加号禁用；减少动态效果开启时退化为瞬时淡出。
- 对话形态（Claude 桌面式）：用户任务以右对齐气泡呈现（`muted` 底、`rounded-2xl` 大圆角、右下角小切角）；Agent 回复一律**不用气泡、不用卡片**——以左侧时间线（细竖线 + 空心圆点）串起的纯文本流逐行展开。
- 续接线程：完成 / 错误终态后，对话流留在原位；用户继续输入时追加为下一条用户气泡并沿用上一轮上下文，Agent 时间线继续向下生长。只有点击「新建对话」才清空当前上下文并回到品牌空态。
- 近溢出横幅：当会话上下文已接近模型上限且当前未运行任务时，在输入框上方展示非模态横幅，文案为「上下文已较长，建议开启新会话以获得更好效果」；主操作「新会话」触发新建对话，次操作 / 关闭「继续当前会话」只收起横幅，不阻塞输入。横幅使用安静的提示色、8px 圆角，不抢焦点，不用 toast 或模态。
- 需补充信息：当 Agent 调用 `ask_user` 时，在对话流末尾展示中性问题提示，明确显示问题和「请在下方输入回答」；保持停止按钮可用，只解锁底部回答输入与发送按钮，禁用新建对话、历史和模型切换。提交回答后提示消失并继续原任务，不展示人工接管按钮。
- 对话页横向尺寸固定：sidepanel / 历史详情 / Hub 对话列均禁止出现横向滚动或被长内容撑宽；URL、JSON、工具入参/输出、长段落等超长内容默认截断，点击文本本身在原位展开/收起（最终结果正文例外：完整展示、不截断，见「完成」）。
- 步骤行：主行为该步目标短句（约 13px 正文色），次行为等宽字体动作摘要（动作名 + 入参 + `→` 输出，单行截断）；点击行展开「评估 / 记忆」全文与原始请求/响应（调试用）。观察事件为时间线上的灰字一行。
- 执行中：流末尾显示活动行——时间线位置脉动圆点 + 扫光（shimmer）文字（「思考中…」「执行 x…」「重试中 (n/m)…」）；遵守 §8 减少动态效果时退化为静态灰字。停止按钮常驻。LLM 中途重试合并为一行琥珀色提示（可展开错误详情）。
- 完成：最终结果不落卡片——「状态标识行（✓ 已完成 / ✗ 未完成 + 向右消散的渐变细线）+ 结果正文（14px、宽松行距，按 Markdown（GFM）渲染：标题 / 列表 / 表格 / 代码块 / 行内代码 / 引用 / 链接等；不渲染裸 HTML）」直接排印在流末，带淡入动效；写入历史。结果正文完整展示、不折叠（它是用户要的答案）；横向严格不溢出（见行61）——代码块与表格在各自框内横向滚动，长词 / URL 换行；链接新标签打开（`rel=noopener noreferrer`）。
- 错误：终态错误以软色提示块呈现（`destructive/10` 圆角底、无边框）：错误信息 + 下一步动作文案 + 原始响应可展开，可重试；用户手动停止（Task aborted）显示为灰字「已停止」一行，不按错误渲染。
- 需人工接管：与普通提问明确区分的醒目提示卡，说明原因（登录 / 验证码 / 2FA / 权限确认 / 不可操作区域 / 模型卡住）、当前目标与卡住动作；按钮为「已完成，继续」或「我已接管，继续」+「暂停」。暂停后保留对话上下文，并在卡片上提供「继续」。
- 历史列表以卡片承载每条记录，不使用列表分割线；卡片内展示任务、状态、时间、步骤数与操作按钮。「前往会话」恢复该记录的任务与事件流并返回当前侧栏对话上下文；重新运行、导出 JSON、删除仍作为辅助动作。
- 历史详情页与问学 Hub 事件流复用同一 `Conversation` 对话流渲染：保留用户气泡、Agent 直出时间线、运行中思考态、错误态与最终结果终态；历史详情页提供「前往会话」入口；Hub 内容列居中、限宽。

## 7. 屏幕规范

**桌面主窗口（2026-06-26 起）**：

- 无边框白色 App 窗口，默认约 1120×720，最小约 920×600，可缩放，不默认最大化。
- macOS 使用 `hiddenInset` 保留左上红绿灯但不显示标题栏文字；Windows / Linux 使用 frameless 窗口与自绘最小化 / 最大化 / 关闭按钮。顶部拖拽区不可见，所有可点击控件必须位于 `no-drag` 区域。
- 应用窗口标题、dock / 任务栏图标与窗口图标均使用问学品牌 logo，不出现 Electron 默认图标。
- 左侧常驻 64–72px 图标侧栏：品牌 logo / 浏览器 / 日志 / tokens / 设置；当前页使用实色主色按钮 + 反白图标，不使用侧边强调条。悬停与键盘聚焦都显示文字提示。
- 主区路由：浏览器多开页、日志页、tokens 统计页、设置页。顶部 38px 为独立拖拽 / Windows 三键区，页面内容从其下方开始；不以挤压页头的固定右内边距模拟安全区，任何断点下页面按钮都不得与窗口控制重叠。
- 浏览器页以单一列表边界为主，列表上方用紧凑文字摘要展示画像 / 运行 / 启动 / 异常数量，不使用四张指标卡。行内展示复选框、画像色块、展示名、状态点 + 文案、上次使用和文字主操作；停止为就近图标动作，重命名 / 复制 / 打开目录 / 删除收进「更多」菜单。更多菜单进入顶层定位，不能被列表或批量条裁切，支持方向键、Home / End、Escape 与外点关闭。多选时底部浮出批量操作条；批量任务执行期间锁定筛选、选择与行操作，失败项保留选择供重试。
- 浏览器页搜索覆盖名称 / ID / 画像目录；排序控件提供最近 / 状态 / 名称三种真实排序。搜索结果为空时保留全量摘要并显示「没有匹配的浏览器 / 清除搜索」，不得误报为尚未创建画像；异常行主操作为「重试」，更多菜单提供「查看日志」。
- 日志页以等宽实时流为主，级别 / 来源筛选与导出在顶部工具条，详情在原行展开，不撑宽页面。「跟随最新」同时负责轮询与滚动到底部；用户上滚时自动暂停。筛选无结果显示「没有匹配的日志 / 重置筛选」，不得复用无日志空状态。
- Tokens 页使用单一总览条展示总 tokens、输入、输出与估算成本；画像 / 模型分布并列，日期趋势以全宽数据流呈现，最近调用使用表格，不堆叠四张同构卡片。成本文案明确仅供参考。进入页面自动刷新，并提供显式刷新与 JSON 导出；无数据时只显示说明，不渲染无效按钮。
- 设置页使用左侧分类 + 右侧表单，枚举值显示为用户可理解的中文，数字项显示单位、范围提示与行内校验。改动串行自动保存，无保存按钮；顶部以「修改后自动保存 / 正在保存 / 已保存」表达状态，保存失败时回退到已持久化值。只把已有真实消费者的项目做成可交互控件：批量启动并发 / 间隔、运行中退出处理、日志保留 / 条数 / 级别与导出格式；仅落盘而未接入运行时的字段用规划说明呈现。账号入口独立于工作台：未登录显示可按 Enter 提交且防重复提交的登录 / 注册表单，已登录在头像菜单显示当前用户与退出入口；用户名字段提示“5–24 位、以英文字母开头、仅含英文字母和数字”，密码字段提示“9–32 位、首字符为字母或数字，并至少包含大小写字母、数字、允许的特殊字符中的三类”。登录与注册提交都先做同一格式校验；无效时保持可编辑、不进入处理中、不发网络请求，并在字段附近给出具体中文修正说明。注册网关、登录 SDK 与激活请求每阶段都必须有 12 秒 UI 等待上限并清除计时器；注册后激活失败时撤销刚建立的 SDK 登录态，不进入工作台，并保留原始可执行错误提示。账号切换期间旧 Tokens 请求不得回写，存在启动 / 画像 / 设置任务时先等待任务完成再退出；退出时显示「正在退出」并先安全关闭当前账号全部浏览器，浏览器关闭失败则留在当前工作台并提示重试。Cloud signOut 已确定失败且 SDK session 仍存在时可恢复工作台；signOut 超时导致结果未知，或云端已退出但主进程清理失败时，必须保持画像锁定并提示用户重新打开问学。退出和切号不删除本机画像；下一账号只看到自己的画像，原账号在同一设备再次登录后恢复原列表。界面不得使用“已同步到云端”等跨设备承诺；「关于」必须直达设置页关于分类；不展示机器 token、复制 token、手动同步 token 或验证码入口。

**退出确认对话框**（浏览器运行中关闭 App 时）：标题「浏览器仍在运行」，正文一句话，按钮「仅退出问学」（默认）/「一并关闭浏览器」（呼应 ARCHITECTURE 的 requestShutdown 契约与"不连坐"决策）。

**浏览器侧边栏**（fork 上游，品牌化改造）：品牌头部（左上角无底 slogan 字标，与内容区之间不设分隔线）+ 对话流 + 底部输入框；历史列表沿上游信息架构，设置齿轮改为三点更多菜单。界面内品牌名一律用「问学」，不再出现 "Page Agent Ext"。

**插件 options 设置页**：浏览器标签页形态打开，左侧为分类侧边栏（模型 / 语言 / 高级 / 日志 / 关于），右侧为对应设置内容。关于区始终放在页面最底部，仅展示版本 `v0.0.1` 与原有外部链接，不展示构建归因信息。页面采用宽松的双栏设置组：每组左侧为标题与说明，右侧为实际控件；分组之间留足垂直间距，避免连续紧凑卡片堆叠。左侧分类选项卡使用问学自绘按钮，不使用通用 Button variant 的默认选中态；选中、悬停与焦点状态带轻量高亮。页面滚动时，左侧分类必须根据当前视口位置自动聚焦高亮；点击分类仍平滑滚动至对应区域。插件 options 不展示账号、登录、用户认证令牌、问学 Hub 入口或任何机器 token。模型区顶部为默认模型自定义下拉菜单（内置 `qwen3.7-max` / `qwen3.7-plus` + 已添加自定义模型），下方为自定义模型列表与加号按钮；添加模型时弹出带缩放/淡入淡出动效的对话框，字段为厂商、URL、API Key、模型名，厂商预设先含 DeepSeek 与千问，选择内置厂商后自动填 URL；厂商下拉最下方为「自定义厂商」，选中后显示厂商名称输入框，URL 由用户自行填写。默认模型、厂商、界面语言、回复语言均使用问学自绘下拉，不使用浏览器原生 `<select>`；下拉弹层打开/收回时有缩放、淡入淡出、顶部光线与选项选中反馈。厂商下拉与自定义模型列表展示厂商标识：内置厂商使用固定标识，自定义厂商使用用户输入名称生成本地标识；鼠标悬停到其他选项时，当前已选项不保持高亮，仅保留勾选状态。每个自定义模型单独保存 API Key，添加后出现在默认模型下拉菜单。语言、高级、日志、关于区保留原设置面板能力：界面语言、回复语言、系统指令、`llms.txt` 与包含所有标签页开关、本地日志保留配置、版本与外部链接。模型 `tool_choice` 兼容由运行时自动判断，不向用户暴露协议开关；`llms.txt` 默认关闭并在开关下说明仅建议可信网站开启；包含所有标签页默认开启但允许用户显式关闭。设置项修改后自动保存，不提供保存按钮；保存完成后在顶部短暂显示「已保存」反馈。

## 8. 可访问性

- 全键盘可达：主按钮、对话框、侧边栏输入、桌面导航、筛选器、画像选择与更多菜单均可 Tab 聚焦，焦点态可见（`ring` token）；弹层支持 Escape 关闭并回到触发点。
- 对比度沿 shadcn 默认 token（满足 WCAG AA）；状态不只靠颜色——状态点配文字标签。
- 路由、分段控件、筛选器与展开行分别暴露 `aria-current` / `aria-pressed` / `aria-expanded`；错误提示使用 `role=alert` 且允许多行，不得以成功色表达错误。
- 遵守系统"减少动态效果"偏好：开启时禁用打字动画与遮罩过渡。

## 9. 文案语气

- 简体中文为主，直接、具体、不卖萌；不滥用感叹号与表情。
- 错误文案 = 发生了什么 + 下一步动作（例：「浏览器异常退出（代码 11）。可点击重新启动，或查看日志定位原因。」）。
- Agent 过程文案用动词开头的短句（「正在阅读页面…」「点击第 3 题选项 B」）。
- 涉及能力边界时如实陈述（PRD §7.2），不过度承诺。

## 10. 性能预算

- App 冷启 → 主窗口可交互 ≤ 2s。
- 点击启动 → 浏览器可用 ≤ 10s（PRD F1 验收）。
- 侧边栏打开 → 可输入 ≤ 1s。
- 安装包（含内置 CfT）≤ 350MB；状态卡过渡不掉帧（60fps 档）。

## 12. 新标签引导页（NewTabHome）

> 本页回归克制白底仪表盘：不使用四周 Liquid Glass、跑马灯、WebGL 门场景或铺底光效；动效只服务组件出现和 onboarding 状态变化。

- 形态：接管新标签页（chrome_url_overrides.newtab），自包含于插件域，桌面端零改动。
- 背景：固定白色，不跟随系统深色，不放光晕、渐变、边缘流光或跑马灯。
- 入场：设置按钮、刷新按钮、字标 hero、快捷入口、首次 onboarding 同时从底部向上滑入；不做错峰、不做模糊大光效；prefers-reduced-motion 时直接静态呈现。
- 内容：字标 hero、快捷入口磁贴（默认百度 / 学习通 / 必应中国，支持增删改排序）、4 步 onboarding（可折叠）、右上角刷新与设置入口。
- 快捷入口：整组始终水平居中；磁贴按固定单元宽度自动换行，新增/删除入口时整体中心不漂移。
- onboarding：点击「第一次使用问学」展开与点击「知道了」收起时使用局部、短促、低饱和的魔法粒子/缩放效果；减少动态效果开启时退化为瞬时状态切换。

## 13. 官网文档页（Website Docs）

- 形态：文档页参考 page-agent 文档站，为顶部导航下方的两栏 README 阅读界面，每个文档板块是独立 hash 子页（如 `#docs/overview` / `#docs/customer-start`），不使用首页式 hero、不保留正文顶部「回首页 / 下载 / GitHub」按钮；顶部固定胶囊导航仍作为全站导航存在。
- 左侧：大目录导航，按「介绍 / 功能特性 / 高级」等文档组组织，桌面端 sticky 于视口左侧并独立滚动，顶部贴近全站导航下方分隔线；移动端折叠为正文上方的目录块。
- 中间：解析后的 README 式正文，每次只渲染当前板块内容，使用大标题、说明段、徽章条、语义标题、段落、步骤列表、浅色功能卡片、表格、代码块、提示块与素材占位；文档内容必须同时覆盖客户教程与开发者接入，不能只放营销摘要。
- 右侧：不设置本页小目录导航；桌面端和移动端都把宽度让给左侧目录与正文阅读区。
- 客户教程：必须写清从浏览器工具栏进入问学、从扩展程序菜单找到问学、将问学固定到浏览器工具栏、输入第一条任务、人工接管与最终提交边界。
- 开发者文档：必须提供可复制的命令或代码示例，并明确官网域、桌面域、插件域的模块边界。
- 素材：没有真实截图/动画时使用明确「待补素材」占位，写明所需画面、建议标注和替换方式；不得用虚构截图冒充真实界面。

## 14. 应用内消息与更新弹窗（固定规范）

> 后台预览、Electron 实显与未来 Chromium 表面共用本规范。后台只改文字、目标、重要性和有效期，
> 不得配置颜色、图标、布局、按钮或关闭规则。

- **目的与风格**：高优先级、低频的系统中断；采用 brutally minimal / industrial utilitarian，克制
  白底、无声音、无玻璃特效或营销插画。
- **色彩与字体**：只用现有 `background/foreground/border/muted/primary/destructive/ring` token；
  沿用项目批准的 PingFang SC / Microsoft YaHei 系统字体栈，不另引网络字体。
- **布局**：Portal 居中，宽 `clamp(520px, 52vw, 560px)`，窄窗口留 20px 边距；4px 状态轨 + 40px
  专业线性图标列 + 左对齐正文，8px 圆角、细边框、轻遮罩。
- **消息**：固定图标、标题、纯文本正文、可选“查看详情”与域名、固定“我知道了”。普通消息可由
  关闭按钮/Escape/遮罩/按钮确认；重要消息无关闭按钮且只允许按钮确认，但始终允许退出 App。
- **更新**：固定版本徽标、说明、大小/进度/速度和“未签名安装包”提示。可选更新显示
  “稍后 / 下载更新”，ready 后显示“稍后 / 打开安装包”；强制更新只保留当前动作、重试与退出 App。
- **打开复核**：点击“打开安装包”后先完成实时 policy 复核；成功后进入 `opening`，系统接收打开
  DMG/NSIS intent 后进入 `handedOff`。断网、pause/withdraw 或候选变化时保留当前可启动版本并显示重试，
  不以缓存 mandatory 策略授权打开。应用不关闭自身或 CfT，后续安装步骤完全由用户和操作系统完成。
- **优先级与无障碍**：强制更新 > 重要消息 > 普通消息 > 可选更新，一次一条；focus trap、
  `aria-modal`、焦点恢复与 alert 语义必需。动效不超过 200ms，减少动态效果时瞬时切换。
- **后台**：“消息推送”左侧编辑、右侧复用同组件预览、下方历史；“版本更新”只选 CI verified
  候选及 rollout，产物 URL/hash/签名不可编辑。设置“关于问学”增加“检查更新”和当前状态。

# 问学 WenXue — 统一 UI 设计指导

> 状态：已批准，2026-09-18。用户以本轮浏览器画像页为基准，授权本规范覆盖此前 UI 视觉要求。
> 同日后续调整：用户明确要求浏览器内插件侧栏 UI 与动效恢复上一版。该表面的例外以 §10 为准；桌面、插件设置网页、新标签页及 Hub 独立页面继续使用新版规范。
> 本文是问学当前 Electron + CfT、插件、后台与官网的唯一视觉规范正文；Chromium 重构方案已于 2026-09-25 废弃，其历史引用不构成当前实现要求。
> 产品范围、数据隔离、安全和功能契约由当前 `PRD.md` / `ARCHITECTURE.md` 定义。
> 旧设计稿、生成提示词、截图和执行日志仅作历史依据，不得恢复与本文冲突的视觉要求。

## 1. 设计哲学

问学是一件让用户专注于任务的工具。界面帮助用户找到内容、理解状态、完成操作，然后退到内容之后。

1. **内容优先**：名称、任务、设置值和结果是第一层。元数据退居辅助层，技术信息在需要时展开。
2. **安静且清晰**：白色承载内容，黑色表达主操作，中性灰组织层级。颜色只解释状态、类别或真实识别信息。
3. **用排版和留白组织内容**：先用标题、间距和细分隔线，再判断是否需要容器。避免每组内容一张卡片、卡片再包卡片。
4. **一个明确的下一步**：每个局部任务有明确主操作；低频动作放更多菜单，批量动作按需展开。
5. **操作可预期**：相同动作使用相同名称和控件。搜索、筛选、自动保存、取消、失败重试都有明确反馈。
6. **状态真实且可恢复**：不展示没有实现的控件，不用假数据装饰，不让错误清空用户输入。用户始终可以停止 Agent 或处理阻塞。
7. **跨页面一致，密度因任务而异**：设置页可以宽松，日志和对话可以紧凑；共享字体、颜色、控件、焦点和文案规则。

视觉来源为问学插件已有的中性组件语言，以及 [OpenAI UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines) 的系统字体、清晰层级、合理留白与单色图标。2026-09-18 获认可的桌面浏览器画像页是参考实现，而非要求所有页面复制同一布局。

## 2. 品牌与适用范围

- 品牌中文「问学」，英文 WenXue，slogan「ask for everything」。沿用现有问字 Logo 和已交付图标资产。
- 适用桌面浏览器、日志、Tokens、设置、登录 / 注册、弹窗；插件侧边栏、历史、设置、新标签页、Hub；后台预览与后续官网 / 目标浏览器 UI 也引用同一规范。
- 当前桌面和插件独立页面以浅色为验收基线。本轮不新增深色主题；不得因系统深色自动变为未验收的配色。
- 页面加载直接展示可用结构，无品牌启动屏、Logo 漂浮、粒子入场或整页编排；未登录的桌面登录页采用下述 §7 一次性品牌入场特例。
- macOS 原生磨砂外壳是系统材质的明确用途，内容页保持不透明；不得把玻璃装饰推广到网页卡片。

## 3. 色彩 token

颜色通过语义变量引用，不在页面内随意建立新色板。桌面 `--wx-*` 与插件语义 token 名称可以不同，含义与取值须一致。

| 语义                 | OKLCH 基准      | 用途                    |
| -------------------- | --------------- | ----------------------- |
| background / surface | `1 0 0`         | 内容背景、表单和菜单    |
| foreground           | `0.145 0 0`     | 正文与标题              |
| primary              | `0.205 0 0`     | 主要按钮、核心选择      |
| primary-foreground   | `0.985 0 0`     | 深色按钮内容            |
| muted / subtle       | `0.97 0 0`      | 分组辅助面、轻选择态    |
| hover                | `0.955 0 0`     | 可交互项目悬停          |
| selected             | `0.94 0 0`      | 选中行                  |
| muted-foreground     | `0.51 0 0`      | 次级说明、占位符        |
| border               | `0.92 0 0`      | 轻分隔线、控件轮廓      |
| control-border       | `0.64 0 0`      | 需要明确识别的复选框等  |
| ring                 | `0.62 0.03 255` | 桌面柔和焦点光晕的基色  |
| success              | `0.46 0.10 150` | 成功 / 运行中的点或文字 |
| warning              | `0.50 0.09 75`  | 等待、需注意            |
| destructive          | `0.52 0.19 27`  | 错误、删除等危险操作    |

正文和辅助文字对比度至少 4.5:1，大文字至少 3:1。状态配文字或图标，不只改变颜色。图表颜色承担分组含义，避免大面积鲜艳统计卡。品牌 Logo、网站 favicon 和用户定义画像识别色保留其真实颜色。

## 4. 字体、间距与形状

- 系统字体：`system-ui, -apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif`。日志、ID、代码和版本号可用 `ui-monospace`，不引入远程字体。
- 独立页面标题 28px / 600，紧凑断点 24px；分组标题 16–18px / 600；名称 15px / 600；正文与控件 14px；辅助文字 12–13px。普通中文说明不缩为 10px。
- 正文行高 1.5–1.7；说明性段落限宽约 65–75ch；标题字距不紧于 -0.04em。
- 以 4px 为间距基础：4 / 8 / 12 / 16 / 24 / 32 / 40 / 48。页头与工具栏分开，组间 24–32px，标签与说明 4–8px。
- 桌面内容常规边距顶部 48px、两侧 40px、底部 24px，窄窗口两侧 24px；内容最大宽度约 1040px。插件设置 / Hub 用居中限宽工作区；窄侧栏使用 12–16px 内边距。
- 正常表单控件 40px 高，列表内辅助动作 32px；普通圆角 8–12px，内容外壳 / 对话框最多 16px。主要及轻量操作按钮可用胶囊形；登录表单外框按 §7 的参考图特例。
- 一般平面不用阴影；菜单可用短阴影（模糊不超过 8px）与轻边框；登录表单按 §7 使用极轻柔光，其余平面不使用边框加大范围弥散阴影的装饰卡片。
- 线性图标统一来源与笔画，常规 16–20px；纯图标按钮必须有可访问名称和 tooltip。

## 5. 控件与交互

- 主要操作：黑底浅色文字；辅助操作：白底细轮廓；局部低频动作：无底图标。控件有 hover、focus-visible、active、disabled、loading 与 error 状态。桌面聚焦采用低透明度、约 3px 扩散与 9px 柔光，替代黑色实线圈；输入边框轻微加深，组合搜索框只在外层发光。系统强制颜色模式恢复可见轮廓。
- 搜索独立于页头描述，提供清空入口；清空后焦点回到输入框。搜索无结果和首次使用空状态明确区分。
- 筛选用轻灰选中底与真实数量，排序使用熟悉的选择器。批量模式显式进入，支持当前结果全选 / 半选，不静默选择隐藏结果。
- 设置按组平铺，以标题 / 说明和实际控件组成行。运行偏好改动自动保存，反馈「正在保存 / 已保存 / 保存失败」；账号资料使用显式保存。不为没有消费者的设置造可操作控件。
- 名称行内编辑：点击对号、Enter 或焦点离开编辑区保存；取消按钮 / Escape 放弃修改；组词中的 Enter 不提交。失败保留草稿；异步返回不能清空新的编辑状态。
- 长内容应换行、局部滚动或按实际用途截断；页面本身不横向溢出。名称可截断并提供完整 title；最终结果必须可完整阅读。
- 桌面菜单和下拉选择全部自绘，使用 Portal 与固定定位逃逸滚动裁切，并根据真实尺寸在窗口边缘翻转、夹取。方向键、Home / End、Escape 可用；取消恢复触发点焦点，点击其他控件不抢焦点。下拉箭头离右侧至少 12px，文本为其预留空间；候选用勾选与浅灰底表示当前值。菜单约 160ms 淡入与 4px 位移，减少动态效果时关闭位移。
- 模态用于有明确边界的编辑或重要中断；具备焦点圈定、Escape 规则和焦点恢复。桌面询问、删除、清空、退出和关闭失败提示均使用应用内自绘弹窗，取消为安全默认操作；不调用系统确认框。破坏性动作保留确认，说明影响范围。
- 无候选更新错误使用可关闭的顶部提示；关闭后不再遮挡内容，“关于问学”仍显示原因。版本号从构建元数据读取，桌面、插件和官网统一显示当前产品版本；不在界面或规范中固定旧 beta 版本字符串。当前过渡版为 `0.1.1-beta.1`。
- 不通过减少空白、缩小正文或大量同构卡片来容纳内容；应调整布局、分组和渐进呈现。

## 6. 动效与可访问性

- 普通过渡 150–200ms，使用 ease-out；只说明展开、选择、加载或状态变化。除 §7 登录页特例外，不安排整页入场、不用浮动 Logo、粒子、彩色流光或顶部光扫。
- 运行中使用文字 + 小状态点或行内 spinner；停止入口持续可达。网页操作目标高亮可以保留，但不能用大面积玻璃包边遮住工作内容。
- 遵守 `prefers-reduced-motion`；循环和位移动效关闭，内容保持默认可见。
- Tab 顺序符合阅读顺序，焦点清晰；路由和展开状态用 `aria-current` / `aria-pressed` / `aria-expanded`；错误用 alert，保存反馈用适当 live region。
- 保留系统滚动条和熟悉的表单行为。禁用态不得与可用态混淆，加载时明确哪个操作在执行。
- 视觉验收覆盖真实数据、空状态、长文本、错误、加载、键盘、弹层边缘与最小窗口；fixture 不替代真实账号 / 浏览器 / LLM 链路验收。

## 7. 桌面窗口与页面

### 窗口外壳

默认约 1120×720，最小约 920×600。macOS `hiddenInset`，左侧栏 72px，原生红绿灯起点 `(10, 20)`；保留原生按钮尺寸与点击区域。原生 `under-window` vibrancy / active 材质承载左栏和内容外缘，renderer 根从首次绘制起保持透明，侧栏透明；登录页以自身不透明背景覆盖窗口，登录后切换主页不改变根底色。遵守减少透明度；主内容白色不透明卡片 16px 圆角，顶 / 右 / 底 8px 露底。没有贯穿窗口的竖线。

Windows / Linux 保留现有无边框窗口和顶部 38px 控件安全区。交互控件始终 `no-drag`。外壳、菜单、弹窗及各页不得相互裁切或覆盖。设置子导航与内容处于同一内容卡片中。

按 2026-09-22 用户后续要求，桌面浏览器、日志、Tokens 列表及内容分组、设置项、版本信息、账号退出区域和头像菜单均不使用行间或分组分割线，以现有留白、标题、悬停与选中状态组织内容；设置页 tabs 与下方内容之间保留一条细分割线。保留表单控件、菜单及弹窗的外边框。

### 浏览器

- 页头为「浏览器」、总数与「新建浏览器」。工具栏含搜索、排序、批量模式。
- 状态筛选为全部 / 运行中 / 未打开，存在启动中 / 异常时显示相应入口。
- 平面列表展示名称、最近使用和状态，行间使用留白，浅灰标记辅以小面积识别色；常态不铺出技术 ID。
- 搜索覆盖名称 / ID / 目录；排序支持最近使用 / 名称 / 状态。打开 / 打开窗口 / 重试是行主操作；停止就近显示，更多菜单提供重命名 / 复制 / 目录 / 删除 / 日志。
- 打开浏览器时前台直接进入问学新标签页；账号会话交接作为后台瞬时通道，不显示状态页面，完成后自动关闭，其过程与结果仅进入桌面脱敏日志。
- 新建与复制清除筛选并进入命名；自动保存规则见 §5。批量期间锁定相关操作，已选行在状态变化时继续可见，失败项保留供重试。
- 列表独立滚动，页头、筛选和批量区保持可达。

### 日志

等宽内容只用于日志本身；标题、筛选与动作沿用全局字体。搜索、级别、来源与导出形成清晰工具栏；日志详情原位展开。「跟随最新」负责轮询与滚动，上滚时暂停。无日志与筛选无结果分开，后者可重置筛选。保留真实导出 / 清空能力，不扩大敏感信息呈现。

### Tokens

总量、输入、输出和参考成本用一个紧凑总览区；画像 / 模型分布与日期趋势按数据组织，最近调用为可读表格。避免四张同构大数字卡。进入时刷新，提供显式刷新和 JSON 导出；无数据展示说明，成本标注仅供参考。

总览下方提供原生可展开的成本规则，键盘和指针均可操作；说明内置 Qwen3.7 Plus / Max 的原价、Plus 输入阶梯、缓存不重复计价的公式、历史缓存数据缺失时的估算口径及报价覆盖范围。具体数值以 `ARCHITECTURE.md` 的「内置模型成本估算」为准，不在视觉规范中重复维护。

按浏览器分布以画像 ID 聚合，展示与导出 label 使用当前账号本机画像名称；画像重命名后同步更新。
无画像归属的历史云端记录显示“未关联浏览器”，保留用量且不推测归属；本机不存在的画像保留 ID 作为区分。

### 设置与账号

六类设置（我的、启动、行为、日志、内核、关于）使用轻量分类导航与平面设置组。枚举中文化，数字显示单位 / 范围及行内校验。保留串行自动保存、失败回到持久化值。未接入运行时的字段仅作规划说明。

「我的」展示完整只读 UID 和邮箱，并提供昵称、头像修改及退出登录。昵称与头像通过显式「保存修改」提交，保存中锁定提交和退出，失败保留草稿并就地提示；成功后首页头像与账号菜单立即同步。注册预览、主页头像和账号资料头像统一圆角方形（12px 圆角、居中 cover 裁切），无头像或图片加载失败时使用默认图形，新头像地址到达后重新加载。选择不支持的格式、空文件或超过 2 MB 的图片时立即显示校验提示并保留旧草稿；取消系统文件选择器也保留旧草稿。

未登录页保持浅色，不随系统深色切换。按 2026-09-22 用户参考图及后续反馈细化登录专属视觉：表单内部、输入框及辅助按钮内底直接复用桌面内容区的 `--wx-surface` 纯白色 `#ffffff`，仅外层页面使用 `#fcfcfb` 浅暖灰形成更轻微的色差；外框为 `#e4e4e3` 细边框、32px 圆角与低透明度柔光，输入框 / 按钮为 10px 圆角。主按钮为 `#0b0b0b` 配浅色文字，保留中文系统字体。

首页居中标题「欢迎回来」固定 32px，下方间距固定 64px；表单宽 448px、标准内边距 28px，输入框与按钮高 40px、文字恢复原有 14px，密码匹配层同步使用 14px，控件间距 16px。仅整体居中位置随窗口高度移动，标题、控件尺寸、外框内边距和各段间距不因窗口高度变化；高度不足时纵向滚动，不压缩表单。窄宽度可适配外框宽度与横向留白。上述 token 仅作用于认证界面。

入口按顺序为单色账号图标配「使用账号密码登录」、分隔文字「或」、完整邮箱输入与「使用邮箱继续」。主按钮下保留中文隐私说明，仅「隐私协议」四字临时链接到问学官网首页（与插件关于页同址），不显示 Google 登录或第三方隐私文案。

按 2026-09-22 用户要求恢复旧版约 2.1 秒品牌开屏：问字 Logo 入场、左移并展开 slogan、淡出，再展示表单。登录内部切换不重播；系统减少动态效果时直接显示表单。注册步骤切换使用约 180ms 淡入与 6px 轻位移，焦点转到当前标题，不弹跳、不整页缩放。

邮箱验证码通过后，已有用户进入工作台；新用户分两步注册：第一步设置密码和确认密码，点击「下一步」校验后进入第二步设置头像和昵称。头像与昵称均可选；空白昵称由认证服务自动生成 `user` 加六位数字，昵称允许重复且仅用于展示。第二步「上一步」保留内存草稿；返回邮箱入口、关闭或切换邮箱丢弃未提交资料和验证凭据，再次进入须从邮箱验证开始。校验邮箱与第一步不得创建服务器账号；仅第二步「完成注册」通过校验后建号。头像选择先本机预览，最终注册后才上传；失败可重试或移除头像，不能重复建号。

账号创建后的登录确认失败不能显示为注册资料未提交或头像失败。临时网络/服务错误提示账号已创建，并重试同一账号的登录确认；明确的身份拒绝返回密码登录并说明需重新登录。只有头像保存阶段的失败才展示头像重试提示。

密码登录使用完整邮箱与密码；「忘记密码」进入完整邮箱 → 验证码 → 新密码及确认流程，重置成功返回密码登录。注册与重置使用相同密码规则：8–32 位、首位英文字母，大小写 / 数字 / 允许特殊符号至少三类。既有密码登录仅检查非空。密码框提供独立可访问的显示/隐藏按钮，默认隐藏。输入确认密码时恢复上方密码逐字绿色/红色匹配动画及活动字符跟随；遮蔽状态只显示圆点，配合文本说明状态，减少动态效果时保留着色但关闭动画。支持 Enter、清晰字段标签、就地错误与防重复提交。

发码成功后显示按邮箱共享的重试倒计时；登录入口、忘记密码入口和重发按钮均显示该邮箱的剩余等待时间，返回或切换流程不重置。同一邮箱冷却不影响其他邮箱、密码登录或已收到验证码的校验。平台限流时显示安全提示并退避，倒计时只表示可以再次尝试，不承诺平台届时解除限制；不自动重发。重发失败导致旧挑战被取消时，退回同邮箱入口并清空旧验证码，保留错误与冷却，避免停留在不可验证的页面。过期按平台返回期限处理。图形验证码仅在 CloudBase 要求人机验证时展示，支持刷新、重试和取消，等待用户输入不计入网络超时。页面保留键盘焦点与减少动态效果支持；不显示手机号、用户名、绑定手机或未完成账号恢复入口。

退出先等待在途动作并安全关闭当前账号浏览器；关闭失败留在工作台。云端退出结果未知或主进程清理失败时保持画像锁定并提示重开。切号不删除本机画像且按 UID 隔离，不承诺跨设备同步。头像菜单展示昵称、完整邮箱、头像（无头像时使用默认图形）、「我的」、关于与退出；不展示机器 token 或手动同步 token。

## 11. 应用内消息与更新

桌面实显与后台预览共用简洁中断面：白底、中性系统字体、左对齐标题与正文、12–16px 圆角。宽约 520–560px，窄屏四周留 20px；状态图标就近而小，不使用 4px 彩色侧轨、工业风标签或玻璃特效。

后台只提供标题、纯文本正文、HTTPS 详情、重要性与目标，不远端配置视觉或 CTA。普通消息可关闭 / Escape / 遮罩 / 确认；重要消息只允许确认但保留退出。系统优先级为强制更新 > 重要消息 > 普通消息 > 可选更新，一次一条，必须圈定并恢复焦点。

更新保留版本、说明、大小 / 进度 / 速度、未签名提示，并依据候选的 `installAction` 展示对应操作。schema 1 保留既有手动检查、下载和打开安装包路径；其最多 24 小时的 mandatory 缓存策略可用于离线门禁/下载，但不能授权打开。schema 2 只接受 optional 更新，并按平台能力自动后台下载。

Windows optional 更新可稍后，或选择“退出并安装”：按钮会结束问学桌面进程并交接 NSIS 安装器，不会自动重启问学；立即重启的独立动作标为“立即重启更新”。启动器窗口关闭不会安装。若浏览器仍占用、用户取消、候选变化或实时策略检查失败，说明原因并保留当前版本，允许之后重试。macOS optional 更新可稍后或打开 DMG；若 CfT 仍占用，提示用户先手动关闭浏览器，再打开 DMG，由用户完成覆盖。打开安装器/DMG 前必须实时策略复核，离线缓存策略不能授权交接；不将“已下载”或“已打开 DMG”描述为安装成功。

安装交接后显示结果时区分“安装器已接手”和“目标版本已启动”。只有新打包版实际版本等于目标版本且服务端按历史签名候选核对对应平台 artifactSha512，才显示已确认；仍运行旧版时显示“尚未确认”，不猜测失败。网络暂时不可用时保留待回报状态且不阻止启动；过期或无法验证的记录不得显示成功。关于页可只展示目标版本及“尚未确认 / 已确认 / 交接失败”，不显示签名数据、匿名 token 或完整上报内容。

关于页即使当前更新状态为 idle，也可展示最近一次 `lastInstallAttempt` 的目标版本与事实状态；`prepared` 或 `accepted` 均展示尚未确认目标版本启动的状态，其中 `accepted` 仅表示安装器/DMG 已接手，不表示安装完成。Windows schema 2 进入错误且仍有对应已验签候选时，按 `manualDownloadAvailable` 能力显示“手动下载安装包”；点击由主进程在线复核策略、签名及安装器哈希后在系统浏览器打开已签名 manifest 的 HTTPS 地址。每次点击都重新在线验证；撤回、离线或候选不匹配时拒绝打开并显示普通错误；按钮是否仍显示由最新状态决定，不把失败复核本身描述为自动隐藏。此动作不更改缓存、不退出问学、不表示安装完成，也不保证可以绕过 UAC、SmartScreen 或组织策略；不另加弹窗。

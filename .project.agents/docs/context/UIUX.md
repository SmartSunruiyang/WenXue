# 问学 WenXue — UI/UX 设计指南

> 视觉与交互细节的权威（与 `PRD.md` 并列上游）。视觉/交互改动先改本文，再让派生实现 spec 对齐。
> 本项目有两个 UI 面：**桌面控制台**（Electron 渲染层）与**浏览器侧边栏**（插件 SidepanelApp）。两者共享同一品牌与 token 体系。

## 1. 设计原则（优先级递减）
1. **用户在场、用户可控**：Agent 是协作者不是接管者——任务随时可停止、可人工接管；绝不隐藏 Agent 正在做什么（呼应 PRD §7.3 合规定位）。
2. **过程可见**：每一步操作都有可解释的可视反馈（模拟光标、元素遮罩高亮、侧边栏活动流），用户始终能回答"它现在在干什么"。
3. **不遮挡工作现场**：智能面板以侧边栏形态存在，永不覆盖页面内容；桌面控制台保持小窗，不抢屏幕。
4. **安静与克制**：桌面端常态零打扰，只在异常（浏览器崩溃）时系统通知；不引入与任务无关的动效与声音。
5. **双端一致**：桌面控制台与侧边栏共用品牌、色板语义与文案语气。

## 2. 视觉身份
- 名称：中文「问学」，英文 "WenXue"；slogan "ask for everything"（小写，作副标题排印）。
- 品牌基调：克制、学术、工具感——像一件趁手的研究工具，不做拟人化吉祥物。
- 应用图标 / 插件图标 / 品牌主色：**待定**（PRD 开放问题 #1），定稿前用单色字标占位；资产规格见 §11。
- 无启动屏：主窗口直接呈现（冷启预算见 §10）。

## 3. 色板与字体
- 颜色一律走语义 token（shadcn / Tailwind CSS 变量体系）：`background` / `foreground` / `primary` / `muted` / `border` / `destructive` 等，**禁止散落 hex**；品牌主色定稿后只改 token 层，组件零改动。
- 深浅色模式跟随系统（插件侧上游已支持，桌面侧对齐）。
- 字体：系统栈 `system-ui, PingFang SC, Microsoft YaHei`；版本号/日志用等宽 `ui-monospace`。
- 层级：标题 16–18px/600，正文 14px/400，辅助 12–13px/`muted-foreground`。中文正文不小于 13px。

## 4. 间距与栅格
- Tailwind 默认 4px 基数刻度；组件间距只用预设档（2/3/4/6/8 → 8–32px），不写任意值。
- 桌面主窗口内容区统一 24px 内边距；侧边栏沿上游布局栅格不动。

## 5. 动效与触觉
- 沿用插件上游动效体系（motion 过渡、打字流式动画、rough-notation 元素高亮），不新增花哨动效。
- 页面遮罩与模拟光标：淡入淡出 ≤ 200ms，缓动 `ease-out`。
- 桌面端仅状态卡切换有 ≤ 150ms 过渡；无音效、无触觉反馈。

## 6. 状态系统
**桌面控制台**（单一状态卡表达 BrowserStatus，与 ARCHITECTURE §1.2 状态机一一对应）：
- `idle` 未运行：主按钮「启动浏览器」可用。
- `launching` 启动中：按钮禁用 + 行内 spinner（≤10s 预算）。
- `running` 运行中：绿色状态点 + 「浏览器运行中」+ 按钮变为「聚焦窗口」。
- `error` 异常退出：destructive 色状态卡，给出"查看日志 / 重新启动"两个动作；同时发一条系统通知。

**侧边栏**：
- 未配置：引导态——一句话说明 + API Key 输入（默认已预置百炼 + qwen3.5-plus）。
- 空闲：输入框聚焦，示例任务提示。
- 执行中：流式活动列表（每步一行），停止按钮常驻。
- 需人工接管：醒目提示卡，说明原因（验证码/登录/不可操作区域），任务可继续或终止。
- 完成：结果总结卡 + 写入历史；错误：内联错误卡（含下一步动作）+ 可重试。

## 7. 屏幕规范
**桌面主窗口**（固定尺寸约 480×360，不可最大化，可最小化到托盘区为后续项）：
- 上：品牌区（字标 + slogan）。
- 中：状态卡（§6）+ 主按钮。
- 下：版本 footer（App / 浏览器内核 / 插件 三元组，等宽字体）。

**退出确认对话框**（浏览器运行中关闭 App 时）：标题「浏览器仍在运行」，正文一句话，按钮「仅退出问学」（默认）/「一并关闭浏览器」（呼应 ARCHITECTURE 的 requestShutdown 契约与"不连坐"决策）。

**浏览器侧边栏**（fork 上游，品牌化改造）：品牌头部 + 对话流 + 底部输入框；配置面板与历史列表沿上游信息架构，仅换品牌与默认值。

## 8. 可访问性
- 全键盘可达：主按钮、对话框、侧边栏输入均可 Tab 聚焦，焦点态可见（`ring` token）。
- 对比度沿 shadcn 默认 token（满足 WCAG AA）；状态不只靠颜色——状态点配文字标签。
- 遵守系统"减少动态效果"偏好：开启时禁用打字动画与遮罩过渡。

## 9. 文案语气
- 简体中文为主，直接、具体、不卖萌；不滥用感叹号与表情。
- 错误文案 = 发生了什么 + 下一步动作（例：「浏览器异常退出（代码 11）。可点击重新启动，或查看日志定位原因。」）。
- Agent 过程文案用动词开头的短句（「正在阅读页面…」「点击第 3 题选项 B」）。
- 涉及能力边界时如实陈述（PRD §7.2），不过度承诺。

## 10. 性能预算
- App 冷启 → 主窗口可交互 ≤ 2s。
- 点击启动 → 浏览器可用 ≤ 10s（PRD F1 验收）。
- 侧边栏打开 → 可输入 ≤ 1s。
- 安装包（含内置 CfT）≤ 350MB；状态卡过渡不掉帧（60fps 档）。

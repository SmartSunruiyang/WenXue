# 接入 CloudBase 手机短信登录、手机号绑定和图形验证

- **日期**：2026-09-18
- **关联**：ConsoleUI；目标 PRD F10；[设计](../docs/superpowers/specs/2026-09-18-phone-auth-design.md)；[实施计划](../docs/superpowers/plans/2026-09-18-phone-auth.md)
- **会话上下文**：用户要求核查现有 CloudBase 认证并增加验证码、手机登录；随后明确要求先提交所有既有改动再开工。

## 做了什么

- 确认原密码登录使用 CloudBase Web SDK，注册通过网关调用 CloudBase 用户创建接口。只读查询当前环境，手机号登录提供方已开启；使用已安装的 SDK 2.30.0 源码核对 OTP、用户绑定与图形挑战契约。
- 登录页新增 +86 手机短信验证码登录，保留密码登录/注册。首次短信验证可创建账号；界面提示已有账号先用密码登录后绑定手机号。
- 头像菜单增加同 uid 手机号绑定，验证前后核对账号，刷新资料后确认手机号，再同步现有主进程会话。已有手机号不支持在此入口换绑或解绑。
- CloudBase 要求人机验证时显示原生图形验证弹窗，支持换图、错误重试和取消；服务端验证答案，SDK 继续原请求。图像仅接受受限的位图 data URI，挑战信息仅在内存驻留。
- 发码成功冷却 60 秒，改号/模式切换取消旧挑战但保留冷却；验证码本地挑战 10 分钟后过期。登录仍经过主进程 UserSessionStore → 网关 activate 的 ACTIVE 账号检查。
- 网络请求保留 12 秒超时，等待用户输入图形验证码时暂停计时。SDK 在 UI 超时后仍可能执行，认证锁保持至实际完成；晚到的登录会话清理，绑定超时提示结果未知。getUser/refreshUser 的缓存写入同样受锁保护；外层已超时时拒绝迟到的图形弹窗。
- 调整短信页在 920×600 矮窗口下的间距，修复原生 dialog 居中与刷新后的输入焦点。

# 手机验证注册与身份交接修复

- 前置：先把上一轮未提交的短信登录、绑定与图形验证改动提交为 `31275db`，本轮在该基线上开发。
- 本轮提交：`fix(desktop): 修复短信登录与手机号验证注册流程`，代码与此执行日志同一提交。
- 报错定位：桌面主进程 `UserSessionStore` 调网关 `/v1/auth/activate` 收到非成功响应或 uid 不合时会返回“问学账号身份校验失败，请重新登录”。旧短信登录使用 CloudBase `shouldCreateUser: true`，可能自动创建资料不全的用户；没有真实用户的网关响应，故不将“自动建号”写作已经证实的唯一根因。
- 本轮实现：短信登录 `shouldCreateUser: false`；新手机号进注册，用户名、密码和短信码必填；CloudBase `signUp` 智能识别已存在用户时比较手机号、用户名、创建时间并拒绝复用旧账号，会话退出后弹窗引导转登录；已有账号补全以同 uid 二次短信和 `reauthenticate` 设置密码，再更新用户名。绑定继续依赖 CloudBase 原生手机号唯一性并显示冲突。身份网关拒绝激活时给出独立提示，不能误报验证码失败。
- 文档：同步当前架构、基础设施、UIUX，以及目标 PRD、架构、计划和验收用例；设计与计划存于 `docs/superpowers`。
- 验证：桌面认证和主进程会话 101 项用例通过，Web/Node 类型检查和 ESLint 通过，Electron Vite 构建通过；隔离本地假 SDK 预览逐步验证新号引导→用户名密码→手机验证码→工作台、已有手机号冲突弹窗→转短信登录，以及旧纯短信账号转补全注册页。预览手机号/密码/验证码仅为内存样例，没有真实短信或真实云端账号操作。
- 下一步：在实际 CloudBase 环境以测试手机号验收真实发码、账号状态 ACTIVE、一个手机号只绑定一个 uid、遗留纯短信账号补全，以及网关激活响应；若仍返回身份校验失败，需要采集脱敏的服务状态码与结构化错误码定位网关/云端配置。

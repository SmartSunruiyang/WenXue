# 注册密码规则统一为 8–32 位、字母开头、至少三类

- 日期：2026-09-18
- 归属：当前运行时 ConsoleUI、CloudBaseLlmGateway
- 用户决策：最初提出 6 位 / 两类；获知当前 CloudBase CreateUser 约束后，明确选择沿用 CloudBase 的 8–32 位 / 至少三类，保留首位不得为数字的要求。

## 做了什么

- 桌面实时条件、注册提交校验、提示与错误文案、网关注册校验统一为 8–32 位，首位必须是英文字母；允许字符集合和至少三类规则保持一致。
- 注册与登录分别传递操作模式。登录仍检查用户名格式与密码非空，实际密码交由 CloudBase 验证，避免新注册规则阻断已有数字开头密码的账号。
- 同步 UIUX、TECH-INFRA 与本会话计划；模块和依赖不变，逐位比对及背景样式沿用本会话实现。
- 通过 CloudBase MCP 只读确认当前环境及用户名密码登录已开启；依据 [CreateUser 官方说明](https://cloud.tencent.com/document/product/876/127961) 确认平台密码边界。未修改云端认证设置。

## 验证

- desktop 凭据 / 退出相关 47 项测试、gateway 66 项测试，共 113 项通过。
- 覆盖 7 / 8 / 32 / 33 位边界、英文字母和数字首位、两类拒绝 / 三类通过、非法输入在注册请求前拒绝、旧数字开头密码进入 SDK 登录验证。
- desktop main / renderer 与 gateway TypeScript 检查、desktop 生产构建、变更源码 ESLint、Prettier 和 `git diff --check` 通过。
- 本机隔离预览确认 `AuthTe1` 仅长度条件为红、`AuthTes1` 全绿、`1AuthTes` 仅首位条件为红、`authtes1` 仅字符种类条件为红。
- 使用虚构输入确认 8 位密码能通过表单注册校验并进入本地回调；切换登录后数字开头密码能通过本地校验。未创建真实用户或修改已有用户密码。

# 上线 CloudBase 单实例降耗优化

- **日期**：2026-07-17
- **关联**：ROADMAP「M4.6 后续 — CloudBase 常驻实例降耗」；`specs/cloudbase-cost-optimization/`
- **目标**：在不改变产品功能、外部协议和计费设置的前提下，由 Gateway 接管后台运行时，只保留一个常驻实例。

## 上线结果

- 已回滚未完成的 Gateway 中间版本 `022`，原稳定版本继续承接流量后再开始本轮发布。
- 已部署完整组合运行时 Gateway `023`，按 5% → 25% → 50% → 100% 完成灰度和逐级回归。
- 已将 `/admin`、`/admin/`、`/admin/assets/*` 以及四条 `/api/admin/v1/...` 路由共七条全部切换到 `wenxue-llm-gateway`。
- 已将旧 `wenxue-admin-web`、`wenxue-admin-api` 的在线版本调整为 `MinNum=0`，它们保留为回滚单元，不再承担正常流量。
- 已将 Gateway 在线版本调整为 0.25C / 0.5GB、`MinNum=1`、`MaxNum=2`，业务入口仍有一个常驻实例，不引入正常访问的冷启动。

## 配置变更过程

最初修改了服务级默认配置，但随后检查发现，正在服务的版本仍保留旧规格，因此没有把服务默认值变更误判为生效。之后通过 `SubmitServerConfigChange`，复用各服务最新镜像并以 `CONFIG` / `FULL` / `image` 模式发布版本级配置：

| 服务                 | 生效版本                 | 最终配置                                               | 配置任务  |
| -------------------- | ------------------------ | ------------------------------------------------------ | --------- |
| `wenxue-admin-web`   | `wenxue-admin-web-006`   | `MinNum=0`                                             | `1742748` |
| `wenxue-admin-api`   | `wenxue-admin-api-009`   | `MinNum=0`                                             | `1742752` |
| `wenxue-llm-gateway` | `wenxue-llm-gateway-024` | 复用 `023` 镜像；0.25C / 0.5GB；`MinNum=1`；`MaxNum=2` | `1742758` |

三个配置任务均等待发布完成并确认服务状态正常；每完成一步都重新验证 Gateway 健康检查、后台静态资源和 AdminApi 未授权响应，未在连续配置中跳过中间回归。

## 验证

- Gateway：43 项测试通过，TypeScript 检查通过。
- AdminApi：15 项测试通过，TypeScript 检查通过。
- Gateway `023` 依次在 5%、25%、50% 和 100% 流量阶段完成健康检查；切换路由和三个版本级配置后均再次回归。
- 最终连续 60 次生产健康检查全部返回 200，平均响应时间约 0.165 秒。
- 原后台域名的 `/admin` 与 `/admin/` 返回新登录页；JS 为 975404 字节，CSS 为 7314 字节，MIME、`Content-Length` 和缓存策略均符合预期。
- 浏览器实际打开后台登录页，页面正常渲染且无 console error；因本轮没有使用管理员凭据，未执行真实管理员登录及登录后写操作。
- AdminApi 无 bearer 请求返回 401，CORS 预检返回 204，非法注册返回 400，未知静态路径和目录穿越返回 404。
- 重复发送非法注册探针时曾触发 429，这是既有按来源 IP 的限流行为；停止重复探针后单次非法注册仍按预期返回 400，不是本轮发布回归。
- CLS 日志服务当前未启用，因此本轮以服务状态、配置任务结果、版本流量、HTTP 探针和浏览器验证作为上线证据。

## 消耗影响与计费边界

- 固定常驻计算由三个 `MinNum=1` 实例降为一个 0.25C / 0.5GB、`MinNum=1` 的 Gateway。
- 两个旧服务的在线配置已是 `MinNum=0`；配置发布产生的临时实例会按平台的空闲缩容保护期退出，不再形成固定常驻基线。
- 按现有资源点规则估算，固定计算约为 21,420 点/月，相对原约 107,100 点/月下降约 80%；实际总消耗仍会受到请求量、弹性扩容、流量、存储及其他 CloudBase 资源影响。
- 本轮没有购买资源点、没有开启超限按量、没有修改套餐或其他计费配置。

## 回滚顺序

1. 若仅出现 Gateway 降规格后的容量或延迟异常，先把流量从 `024` 回滚到使用旧规格的 `023`，确认健康检查、静态资源与 AdminApi 后继续保留七条路由指向 Gateway。
2. 若组合后台运行时出现功能异常，先把 `wenxue-admin-web` 和 `wenxue-admin-api` 恢复为 `MinNum=1`，等待两个旧服务发布完成并通过直连回归。
3. 旧服务就绪后，再把七条后台路由切回各自原服务；不得在旧服务恢复前先切路由。
4. 若还需要回滚 Gateway 代码，须在后台路由恢复后再从 `023` / `024` 回滚到原稳定代码版本，最后复验用户 Gateway、后台页面和四条 AdminApi 路径。

## 结论

线上已完成从三常驻实例到单常驻 Gateway 的降耗切换。旧后台服务仍作为可恢复的 Min0 回滚单元保留，正常功能路径不依赖冷启动；当前没有为了降耗更改业务行为或计费授权。
